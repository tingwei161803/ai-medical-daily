三天之內，三家公司各自示範了「AI 自己做生物學」的一種形狀——10/21 GTC Berlin，NVIDIA 與華盛頓大學蛋白質設計研究所把 RFD4-Proteina 以 BSD 3-Clause 開源，4.356 億參數、FP32 權重 1.74 GB、單張 H200 產一個 250 token 設計只要 5.0 秒（regional compilation 後 2.8 秒），在蛋白質結合、小分子結合、酵素骨架、DNA 結合四組 benchmark 全勝受評基線；10/20 Anthropic 公布 Claude 在 Claude Science 裡自主跑約 64 小時、動用 12 個設計工具生成 318,484 個設計、篩過 553,052 組配對、自選 180 個送驗，連同人工補的共 211 個實測只有 17 個過關（單毒素組 11/60、18%），最強的 Cn2-B1 與 Cn2-B2 達個位數 nM，而 Anthropic 自己白紙黑字寫「只證明結合、未證明中和」；10/21 OpenAI 與 PerturbAI、Scripps 用數千個 GPT-Rosalind agent 在 32 分鐘內讀完 800 萬顆細胞的小鼠全腦 CRISPR 圖譜，引用逾 700 篇文獻、對照單一 agent 的 11 篇，盲測專家 75% 偏好分散式產出

本週技術線最值得注意的不是任何單一模型的分數，而是三件事在同一個 72 小時窗口裡同時成立：模型權重真的開出來了（RFD4-Proteina 走 BSD 3-Clause、權重日期 10/19）、agent 真的被放手跑了超過兩天（Claude 約 64 小時、約 10,000 GPU 小時）、而 agent 的規模化真的拿到了對照組（OpenAI 的單 agent 11 篇 vs. 分散式 700+ 篇）。同一週 Epic 宣布把 Connectors 建在 Model Context Protocol 上（Fierce Healthcare，10/21），意味著醫院端的 agent 介面也開始收斂到同一條協定線上。而三份報告的共同腳註也一致：全部是計算結果或體外結合，沒有一個走到療效。

開源模型 NVIDIAUW IPDRFD4-Proteina10/19–10/21

NVIDIA 與 David Baker 的團隊把蛋白質設計模型開成 BSD 3-Clause：4.356 億參數，單張 H200 五秒一個設計

發生什麼

10/21 GTC Berlin，NVIDIA 與華盛頓大學醫學院蛋白質設計研究所（UW Medicine Institute for Protein Design）發表 RFD4-Proteina，一個收在 BioNeMo 平台裡、把「可程式化設計」與「搜尋」綁在一起的開放模型（NVIDIA 新聞稿）。技術規格：flow-matching 架構、同時生成序列與全原子結構、435.6 million 參數、FP32 權重 1.74 GB、以 BF16 執行；單張 H200 上一個 250 token 的設計耗時 5.0 秒，開啟 regional compilation 後 2.8 秒。NIM 部署列出七種任務（generation、motif scaffolding、enzyme design、small-molecule binder design、antibody design、partial diffusion、inverse folding），並支援 diffusion 過程中的 reward-guided beam search。權重日期 10/19，diffusers 支援 10/20 併入，NIM 於 build.nvidia.com 與 NGC 同日上架（unite.ai 技術整理）。

為什麼重要

重點在授權與尺寸的組合。BSD 3-Clause 是最寬鬆的一檔，NIM 卡片直接標註可商用；1.74 GB 的權重意味著一張消費級或單張資料中心卡就跑得動，不需要叢集。這把「設計一個 binder」的邊際成本壓到幾乎是電費，也讓它能被塞進 agent 的工具箱——同一份新聞稿裡，Genedata 的 AI co-scientist 就是用 RFD4-Proteina 在 Danaher 的自主實驗室裡協調設計與測試，而模型同時上架 Amazon Bio Discovery、Anthropic 的 Claude Science、Benchling、Databricks、Google Cloud、Hugging Face、Nebius、OpenAI 與 Tamarind Bio（GlobeNewswire 全文）。一個模型同時出現在三家互為競爭對手的 AI 實驗室的科學產品裡，這件事本身比 benchmark 更值得記下來。

要打折的地方

「四組 benchmark 全勝受評基線」是 NVIDIA 自述，而且出處是尚未同儕審查的 research draft，新聞稿與二手整理都沒有給出任何一個數字——沒有 success rate、沒有 throughput 的絕對值、沒有基線名單。訓練資料組成未揭露。模型卡上的 PD-L1 binder、HER2 抗體改造、酵素催化 motif、小分子口袋四個範例，卡片自己註明不是實驗結合或催化結果。

自主 agent AnthropicClaude ScienceAdaptyv Bio10/20

Claude 自主跑 64 小時設計抗蠍毒結合蛋白：318,484 個設計進去，17 個真的黏住——而 Anthropic 自己先把話說死

發生什麼

10/20 Anthropic Science 團隊公布，用一個內部研究版 Claude 在 Claude Science 環境裡設計對抗蠍毒神經毒素的 minibinder（Anthropic 研究報告）。流程：初始 prompt 之後 Claude 自主運作約 24 小時，之後只收到四次追加指示，全程約 64 小時、約 10,000 GPU 小時；Claude 自己挑毒素結構與 hotspot、自訂品質門檻、選工具、寫報告。標的是四個地區的五種神經毒素：Cn2（墨西哥）、Ts1（巴西）、AaH I 與 AaH II（北非）、LqhIII（中東）。計算量：12 個設計工具、318,484 個設計、co-fold 篩過 553,052 組 design–toxin 配對，Claude 自選 180 個、Anthropic 人工補 31 個，共 211 個送 Adaptyv Bio（無細胞表現）與 Twist Bioscience（哺乳類細胞、Fc 融合）以 SPR 實測。判定門檻訂得很硬：兩間實驗室、每次重複都要是 hit，KD ≤ 1 µM，且對 off-target 蛋白 CLEC12A 無訊號。結果 17/211 過關（Cn2 七個、AaH II 四個、AaH I 四個、LqhIII 兩個），單毒素組 11/60（18%），而所有多毒素設計沒有一個對一種以上毒素達標。最強的 Cn2-B1 與 Cn2-B2 達個位數 nM，競爭實驗顯示其結合位與已知可在小鼠中中和 Cn2 的抗體 LR 重疊或相鄰。

為什麼重要

這是目前公開紀錄裡，把「agent 自主時數」與「濕實驗驗證」綁在同一份報告裡最完整的一次。18% 的單毒素命中率，Anthropic 自己說與一般蛋白質設計活動的水準相當——意思是 agent 沒有變魔術，但它在沒有人逐步指導的情況下，把一個通常需要團隊數週規劃的設計活動跑完了。更關鍵的是失敗的部分也被完整報出來：多毒素泛特異性設計全軍覆沒，這恰好是抗蛇毒／抗蠍毒最需要、也最難的那一塊。全部 211 個設計、預測結構、分數與實驗數據已公開在 Hugging Face。背景尺度：蠍螫每年影響至少 120 萬人、造成逾 3,250 人死亡，多數是醫療可近性不足地區的兒童。

要打折的地方

Anthropic 自己列了限制，而且列得比多數廠商誠實：只測重組毒素，未在細胞或動物測試中和，也未對毒液純化的毒素測試；公司明文表示「未確認中和，不宣稱做出抗蛇毒血清」。下一步需要毒液結合、patch-clamp 電生理與小鼠實驗。另外，211 個裡有 31 個是 Anthropic 員工補的，「完全自主」要打一點折；而 prompt 的改寫由投資研究公司 Citrini Research 協助，這層關係報告有揭露但值得讀者自行評估。

多 agent 架構 OpenAIPerturbAIScripps ResearchGPT-Rosalind10/21

數千個 agent、32 分鐘、800 萬顆細胞：OpenAI 第一次給出「分散式 vs. 單一 agent」的對照數字

發生什麼

10/21 OpenAI 與 PerturbAI、Scripps Research 公布一組他們稱為「distributed biological reasoning」的實驗：數千個由 GPT-Rosalind 驅動的 agent 平行讀一份小鼠全腦 CRISPR 圖譜（約 800 萬顆細胞），每個 agent 負責一個基因擾動，分析細胞反應、檢索文獻、提出機制解釋，最後彙整成一份連結基因、細胞效應、文獻與候選機制的「reasoning atlas」。整段跑完 32 分鐘（OpenAI 公告）。對照組是關鍵：在模型與資源固定的條件下，單一 agent 在最大工作量時只引用 11 篇文獻，分散式版本引用超過 700 篇；盲測人類專家在兩種報告之間，75% 偏好分散式產出。產出的兩條具體假說：小腦中 Tsc2 被擾動改變了數十個神經傳導相關基因的活性、而 Tsc1 幾乎沒變（兩者同屬 mTOR 調控，可能與結節性硬化症的學習與行為困難有關）；以及 Dctn1 擾動後膽固醇合成基因表現上升，被連到膽固醇運輸障礙的既有研究，指向 Perry 症候群的神經退化機制。atlas 公開在 GitHub、資料集在 Hugging Face、論文在 bioRxiv。

為什麼重要

「多開幾個 agent 會不會更好」過去一直是信仰問題，因為大家只報最終效果、不報單 agent 基線。11 篇 vs. 700+ 篇是這一年來少見的乾淨對照：固定模型、固定資源，差異只來自把工作切開平行跑。它同時也點出分散式的真正代價——700 篇引用意味著 700 條需要人去抽查的推論鏈，而 75% 的專家偏好率反過來說，有 25% 的情況下專家寧可要單 agent 那份。對醫療 AI 的意義是方法論上的：如果 agent 數量能這樣換到文獻覆蓋度，那麼「臨床決策支援能不能靠多 agent 補齊 guideline 覆蓋」就從哲學問題變成可設計的實驗。

要打折的地方

「數千個」沒有確切數字；GPT-Rosalind 的架構與訓練方式公告沒有描述。「人類團隊要做數月到一年」是團隊自估，不是量測。新穎性與價值評估「與盲測專家判斷一致」只有定性描述，沒有給一致性統計量。單 agent 對照只跑了一組固定設定，泛化性未建立。兩條假說都還沒有實驗驗證，公告自己也說科學家仍是發現的中心。這是生物研究，不是臨床應用。

協定與介面 EpicMCPAgent Factory10/21

Epic 把 Connectors 建在 Model Context Protocol 上——電子病歷龍頭選了哪條線，整個生態系就得跟著接哪條線

發生什麼

10/21 Open@Epic 大會前，Epic 宣布 Connectors：讓第三方 App 開發者把自家應用接進 Epic 的 AI agent，使 agent 能從外部 App 取資訊、也能在外部 App 裡完成任務（Epic 官方貼文）。適用對象是三個既有助理——病人端 Emmie、臨床端 Art、營收循環與營運端 Penny——以及醫院自建於 Agent Factory 的客製 agent；Agent Factory 於八月使用者大會亮相，上線時帶逾 100 個預建 AI 功能。關鍵的技術選擇：Connectors 初期採用 Model Context Protocol（MCP）。時程是 Epic 會在 2026 年底前與部分醫院夥伴開始測試，開發者做的 Connectors 自 2027 年 3 月起在 Epic Showroom 上架；Epic 會向開發者收上架費，金額未公布（Fierce Healthcare, 10/21）。首批具名夥伴：Availity（給付、事前授權、理賠）、Gozio Health（院內導航）、VPL（藥品配送時程）。

為什麼重要

過去二十年醫療資訊互通的語言是 HL7 與 FHIR——為「交換資料」設計。MCP 是為「讓模型呼叫工具」設計的，解決的是完全不同的問題：不是把一筆檢驗值搬過去，而是讓 agent 在另一個系統裡「做一件事」。Epic 選 MCP，等於替北美醫院的 agent 層訂了事實標準；對第三方廠商來說，這決定了接下來兩年工程資源往哪放。治理設計也值得注意：Epic 說每家醫院自行控制權限、啟用前可檢視該 Connector 能讀什麼、能改什麼，並強調 Connectors 不新增自主行動——把「agent 能做什麼」的決定權明確留在醫院端，這是對 10/19 剛截止的 FDA 生成式 AI 醫材意見徵集裡那場「責任該落在誰身上」辯論的直接回應。

要打折的地方

這是公告，不是出貨：Showroom 要到 2027 年 3 月，測試才剛要開始。Epic 沒有公布任何採用數字——Art／Emmie／Penny 各有多少醫院在用、Agent Factory 有多少 agent 上線，全部沒有。唯二的數字是 100+ 預建功能與評估 Emmie 用的「數千個測試案例」，都是 Epic 自述。上架費未公布，而這對小型開發商是決定性變數。

基礎模型 Mass General BrighamFAHR-FaceLancet Digital Health10/19

4,000 萬張臉訓出的 FAHR-Face 登上《Lancet Digital Health》：一張照片同時給出生理年齡與癌症存活風險，而論文裡最該讀的是它「沒有」建立什麼

發生什麼

10/19《Lancet Digital Health》刊出 Mass General Brigham 的 FAHR-Face（Foundation Artificial Intelligence for Health Recognition），一個以逾 4,000 萬張人臉影像訓練的基礎模型，衍生兩個工具：FAHR-FaceAge（生理年齡）與 FAHR-FaceSurvival（癌症存活風險），DOI 10.1016/j.landig.2026.101056（MGB 新聞室）。通訊作者 Raymond Mak、共同資深作者 Hugo JWL Aerts，經費來自歐盟 ERC。主要發現：FAHR-FaceAge 與實際年齡的差值獨立地與存活相關；兩個工具的預測只有弱相關，代表它們各自捕捉到不同資訊，在外部癌症世代中合併使用能改善存活模型配適；重度飲酒、用藥與抽菸者看起來生理上較老；年齡估計在姿勢、光線、表情、化妝與多數整形術式下穩定，僅隆鼻後有小幅偏移。研究同時開放一般人上傳自拍取得 FaceAge 研究回報（FaceAge Research Study，faceage.bwh.harvard.edu），《波士頓環球報》10/20 報導了這個公開工具。

為什麼重要

這是「最低成本輸入訊號」方向的一個極端案例：不需要抽血、不需要影像設備、不需要病歷，一張臉就能產生兩個與存活相關的連續變數。在放射腫瘤科的語境下，它想解決的是臨床上長期靠主觀印象判斷的「這個病人撐不撐得住積極治療」。兩個工具弱相關這點技術上最有意思——它意味著臉上同時編碼了至少兩類互不重疊的健康訊號。《華盛頓郵報》10/20與CNN 同日報導把它推進了大眾視野，而這恰恰是這類工具最需要小心的地方。

要打折的地方

新聞稿與二手報導都沒有給出任何效能數字——沒有 MAE、沒有 C-index、沒有風險比、沒有信賴區間、沒有開發與外部驗證世代的人數，也沒有具名的對照模型。這是一份計算開發與驗證研究，未測試醫師使用這些分數是否改善決策或結果；生活型態關聯是相關、不是因果；臉部注意力圖顯示模型用了什麼，不等於生物機制；沒有建立臨床決策門檻、治療選擇規則或可安全使用的次族群。MGB 坦言需要更多評估才知道模型在更廣的人口與臨床情境下表現如何——而報導與新聞稿都沒有任何亞群公平性數據，這對一個以臉為輸入的模型是嚴重缺口。另需揭露：MGB 已就下一代臉部健康演算法申請美國臨時專利（No. 63/769,840），Mak、Haugg 與 Aerts 列名。

臨床 agent AbridgeAbridge Assistant10/13

Abridge 把 scribe 升級成 Assistant：把推理步驟攤開給醫師看，引用指到病歷的哪一段

發生什麼

10/13 Abridge 發表 Abridge Assistant：一個在電子病歷內與手機上介面一致的聊天／語音助理，資料來源包含病人病歷（病程紀錄、檢驗結果、外院資料）、當下的醫病對話、臨床指引，以及該醫院自己的臨床路徑與政策庫（Abridge 官方貼文）。任務涵蓋摘要病人近況變化、回答臨床問題、以病歷數值預填計算機、個人化病歷書寫、起草轉診與交班。兩個設計細節值得記：第一，它把複雜請求拆成一串步驟（蒐集脈絡、檢查完整性）並即時顯示執行過程；第二，它標註自己用了病歷的哪些段落與哪些來源，讓醫師能回溯推理。評估方式是以臨床醫師制定的 rubric、由人類與 LLM 雙重評審，在每項功能上線前後都跑。自九月釋出起，所有使用 Abridge 的醫院、所有臨床人員都可使用，無論是否以 Abridge 做文書。公司自述服務逾 300 家企業級醫療體系。

為什麼重要

環境聽寫（ambient scribe）這條賽道的技術天花板已經很近——把對話變成病歷，各家差距在收斂。Assistant 是 Abridge 把既有的 EHR 連線當通路，往「醫師在病歷裡問任何問題」擴張。值得注意的是它與 Epic Connectors 的關係：Abridge 自建助理層，Epic 則在同一週把 agent 層標準化成 MCP。兩者既是互補也是正面對撞——Epic 的 Art 做的正是臨床端助理。而「顯示執行步驟」與「引用指到病歷段落」這兩個設計，是本週在醫院端唯一具體可查核的「可解釋性」承諾。

要打折的地方

Abridge 沒有揭露底層模型供應商、架構、檢索方式、延遲或任何準確率指標，也沒有公布資料保存政策。「300+ 企業級體系」與 Sutter Health 的「78% 臨床人員工作滿意度改善」都是廠商自述、未經第三方稽核；後者是滿意度調查，不是臨床品質或安全指標。「所有臨床人員都可使用」指的是權限開通，不等於實際使用率——後者 Abridge 沒有公布。

治療設備 Siemens HealthineersVarianNemotronHoloscan10/21

Siemens Healthineers 把 agent 放進放射治療計畫：開放權重模型 + CUDA 劑量計算 + 即時感測器串流

發生什麼

同在 10/21 的 GTC Berlin，Siemens Healthineers 與 NVIDIA 宣布共同開發下一代適應性放射治療（adaptive radiotherapy），三個技術元件：以 NVIDIA Nemotron 開放模型驅動的 agentic co-planning（協助腫瘤科醫師評估治療策略）、CUDA 加速的劑量計算做病人專屬模擬、以及 Holoscan 平台把即時感測器資料接進 AI（NVIDIA 新聞稿）。Siemens Healthineers 癌症治療事業 Varian 負責人 Arthur Kaindl 把這項工作與近期推出的 Accela 系統綁在一起，並說「治療應該去適應病人，而不是反過來」。新聞稿引用的尺度預估是到 2050 年全球每年約 3,500 萬人被診斷出癌症。

為什麼重要

本週其他六則都在軟體層，這則是唯一把 agent 推到治療設備上的。適應性放療的瓶頸一直是時間：病人躺在機器上，解剖位置每天都在變，重新規劃劑量要算很久，所以實務上多半照舊計畫打。把劑量計算 CUDA 化加上 agent 協助決策，攻的就是這個「線上重規劃」的時間窗。它同時也是 Nemotron 開放權重策略的具體落點——NVIDIA 不只賣卡，而是讓開放模型成為醫材廠的預設底層。

要打折的地方

措辭是「正在開發」與「正在探索」，不是產品。新聞稿沒有給任何效能數字——沒有重規劃時間、沒有劑量精準度、沒有臨床結果，也沒有時程與法規路徑。3,500 萬人是 2050 年的流行病學推估，與這套系統的效能無關，屬於市場尺度敘事。

02 — Product Analysis

同一個問題（設計一個會黏住標的的蛋白質），兩種完全相反的產品形態：一個把能力壓成 1.74 GB 的權重交給你，一個把能力包成一個會自己跑 64 小時的 agent。

RFD4-Proteina

開放權重的蛋白質設計模型 · NVIDIA × UW Medicine IPD（美國）

功能與定位。flow-matching 架構，同時生成序列與全原子結構，使用者以「要保留什麼」做條件——結合標的、酵素 motif、配體或結構特徵。賣給誰很清楚：任何想把蛋白質設計變成自家 pipeline 一環的人，從藥廠到學術實驗室到 agent 開發者。它不是終端產品，是零件（規格與授權出處）。

  • 優勢 ：授權與尺寸的組合近乎沒有對手——BSD 3-Clause、1.74 GB FP32 權重、H200 上 5.0 秒一個設計，而且同時上架九個平台，包含 Anthropic 與 OpenAI 自己的科學產品。
  • 優勢 ：七項任務涵蓋面廣（含抗體設計與 inverse folding），且支援 diffusion 中的 reward-guided beam search，意味著可以直接接外部打分函數——這是給 agent 用的設計。
  • 疑慮 ：零個公開的量化 benchmark 分數。「勝過受評基線」沒有說勝多少、勝過誰，出處是未經審查的 draft。訓練資料組成未揭露，這對需要評估分布外表現的使用者是真實障礙。
  • 疑慮 ：模型卡上的四個範例全是計算結果，卡片自己註明非實驗驗證。開放權重降低了嘗試成本，但沒有降低濕實驗驗證的成本——而那才是真正的瓶頸。

Claude Science

可長時間自主運作的科學 agent 環境 · Anthropic（美國）

功能與定位。不是一個模型，是一個讓模型自己挑工具、訂門檻、跑完整個設計活動並寫報告的環境。抗蠍毒那份報告裡，Claude 在 Claude Science 內自主運作約 64 小時、呼叫 12 個設計工具、消耗約 10,000 GPU 小時，人類只給了一次初始 prompt 加四次追加（Anthropic 報告）。賣的是「把一整段研究流程外包出去」。

  • 優勢 ：有濕實驗驗證，而且驗證門檻比多數論文嚴——兩間獨立實驗室、每次重複都要命中、KD ≤ 1 µM、加一個 off-target 對照（CLEC12A）。17/211 這個數字是在這個門檻下產生的。
  • 優勢 ：失敗照報。多毒素泛特異性設計全數未達標這件事被寫進報告正文，而且全部 211 個設計與實驗數據公開在 Hugging Face，外部可以自己重算。
  • 疑慮 ：18% 的命中率「與一般設計活動相當」是 Anthropic 自己的定性說法，沒有並列的對照組——沒有「同樣的工具由人操作」的基線，所以 agent 的增益無法量化，只能說它沒有退步。
  • 疑慮 ：211 個裡 31 個由員工加入，約 15%，「自主」要扣這一塊；而約 10,000 GPU 小時換 17 個體外結合蛋白、且未測中和，單位成本與距離臨床的距離都還沒有被認真定價。

一句話收束：本週的競爭結構是一個分層的三明治。最底下 NVIDIA 用 BSD 3-Clause 把模型層壓成公共財、綁住硬體；中間 Anthropic 與 OpenAI 搶的是 agent 的「深度」（64 小時自主）與「寬度」（數千個並行），兩家同時都是 NVIDIA 模型的下游通路；最上面 Epic 用 MCP 與 Showroom 收費閘門把醫院端的入口握在手裡，而 Abridge 這類應用層廠商得在 Epic 的規則下跟 Epic 自家的 Art 競爭。真正沒人站的位置是「濕實驗驗證」——三份技術報告的限制欄全部指向同一個缺口，而那恰好是目前最貴、最慢、也最難用算力換的一段。

04 — Taiwan Angle

開放權重、MCP 與「用現成資料跑 agent」這三件事，對台灣各有不同的門檻高度

(1) RFD4-Proteina 的 1.74 GB 把門檻降到國內實驗室可承受的區間。BSD 3-Clause 加上單張資料中心卡可跑，意味著台灣的學研單位與生技公司第一次能在不簽授權、不租叢集的前提下把蛋白質設計納入自己的流程。真正的瓶頸會立刻從算力移到濕實驗驗證產能——Anthropic 那份報告把 211 個設計送去 Adaptyv Bio 與 Twist 做 SPR 雙重複驗，這種「兩間獨立實驗室、每次重複都要命中」的驗證規格，在台灣目前並沒有對應的商業化服務可以直接買到。能補上這一段的單位，會比買更多卡的單位更有價值。

(2) Epic 選 MCP，對台灣醫院資訊廠商是一個明確的技術時程訊號。衛福部今年主推的 FHIR Box 跨院病歷互通解的是資料交換層，而 Epic 這一步解的是上面那一層：讓 agent 在別的系統裡做事。兩者不衝突，但順序很重要——如果國內只把力氣放在 FHIR 而沒有同步規劃 agent 呼叫工具的權限與稽核模型，等到 2027 年 3 月 Epic Showroom 開放、國際廠商的 Connector 生態成形時，台灣的 HIS 會發現自己有資料標準卻沒有 agent 介面標準。Epic 那套「醫院自行檢視 Connector 能讀什麼、能改什麼」的治理設計，是現成可以直接參考的規格。

(3) OpenAI 那組實驗示範的是「已有資料 + 大量 agent」，這條路台灣的門檻最低。800 萬細胞的圖譜是既有資料，agent 只是把人力讀不完的部分平行讀完。台灣手上最接近這個形狀的資產是健保資料庫與各醫學中心的影像與病理庫。10/5 衛福部的「2026 國產 AI 3D 醫療影像暨元宇宙應用大會」上，台大醫院院長余忠仁表示 2028 年要完成全院自動化 AI 3D 影像轉譯架構，部長石崇良同場提到 FHIR Box 與次世代 3D PACS，智捷醫電的 Anatomy Cloud 平台約 5 分鐘把 2D 掃描轉成 3D 解剖模型、並捐贈 10 台工作站供部署為示範設備。這些都是基礎建設，但要把它變成「數千 agent 在上面跑」，缺的不是模型而是可程式化存取的資料介面與治理授權——也就是第 (2) 點講的那一層。
