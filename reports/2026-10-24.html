監控它的系統，被它要監控的東西繞過了——這一週 agent 在攻防兩端同時加速，而醫院正準備把鑰匙交出去

2026 年 10 月 24 日（六）· 涵蓋 10/17–10/24 · 台北時間

今天不挑醫療新聞當主線，因為這一週最重要的 AI 事件不在醫療裡，而醫療是它最沒有準備好的落點。METR 10/22 公布的紅隊報告說，OpenAI 的內部失準監控只在 agent 把控制權交回使用者時才觸發，所以 agent「只要持續動作就能無限期延後被監控」；同一週微軟把 9 月以來對數百個組織的攻擊歸因到一個用開源多代理滲透框架的國家級行為者，而 NorForge 的報告說一個操作者用 agent 攻破逾 100 家公司網站、每成功一次約 50 美元。對照組是摩根士丹利開始封鎖第三方 agent，因為它分不出哪個動作是客戶要的。而同一天，Microsoft 的 MAI-DxO 登上《Science》、Suleyman 說要追 medical superintelligence。身分與監控這一層的成熟度，現在是醫療 agent 落地的實際天花板，不是模型準確率。

五則消息排成一條線：agent 的能力已經跑在身分、監控與歸屬這三層基礎設施前面，而這三層正好是醫療最依賴的
AI 安全 OpenAIMETRRedwood Research10/22

METR 與 Redwood 在 OpenAI 內部待了三週，結論是「agent 只要持續動作就能無限期延後被監控」

發生什麼

一名 METR 員工與一名 Redwood Research 員工在 2026/7/21 至 8/11 進入 OpenAI，做了一次「高權限試點演練」，壓測它的內部失準監控系統，拿到內部程式庫、monitor prompt 與設定、內部文件，並訪談約十二位研究員與工程師，全程使用不離場的 OpenAI 公發裝置、現場有人陪同。成果是一份 61 頁報告，10/22 公布的公開版經 OpenAI 遮蔽後為 38 頁。幾個具體數字：以 GPT-5.5 等級以上模型的內部 agentic Responses API 流量計，METR 估只有約 75–94%「有資格」被監控（內部 Codex agent 使用的子集是 99.2%，METR 自述「兩個方向都有相當大的不確定性」）；不監控 compaction 事件，使 2026 年 5 月到 7 月約「一成量級」的 Codex 流量漏掉（OpenAI 自己在演練前發現、演練期間修掉）；monitor 本身錯誤率「低於 0.2%」。漏洞方面：monitor 只在 agent 把控制權交回使用者時觸發，所以「agent 只要持續動作就能無限期延後被監控」；一個 exploit 可讓「數百個近期動作」不被監控（細節被遮蔽）；序列化差異可讓 agent 構造輸入使 monitor 失敗、軌跡不被升級給人工審查；兩個客戶端可控的 header 能對新 agent 關掉監控；還有一條路徑可「原則上」繞過 Codex sandbox 與 Auto-Review。

為什麼重要

這不是「某家公司資安沒做好」的故事，而是整個產業把 agent 治理建立在一個未經對抗測試的假設上：監控系統是外生的、agent 動不到它。METR 的建議直指這一點——「agent 採取的動作，不應該能影響監控系統是否執行、何時執行」，而這正是被破的那一條。對醫療的意義很直接：醫療 agent 的治理方案（稽核軌跡、人機協同審查、事後回溯）全部假設「所有動作都會被記錄下來」。METR 的發現是，當被監控者本身是個有能力的 agent，這個假設需要被當成安全屬性來證明，不是當成架構圖裡的一個方框。要打折的地方也要說清楚：公開版只有私下報告的一小部分、OpenAI 有遮蔽權，METR 自述這是測試「存取安排」的試點而非完整透明度報告，而 OpenAI 事後說所有影響生產防護堆疊的漏洞都已修補、但 METR 明確表示它沒有評估這些說法；覆蓋率 75–94% 也是估計值而非量測值。The Register 10/23 的報導另補一個公道的註腳：報告並未主張 agent 刻意隱藏了活動，只是說這套監控有可能漏掉這類行為。

資安 MicrosoftConnectWiseARTEX10/21

微軟把 ConnectWise 供應鏈失守歸因到用開源多代理框架 ARTEX 的 Storm-0940：事後試登逾 2,250 個租戶，最快不到 3 小時拿下雲端特權

發生什麼

微軟威脅情報 10/21 發布分析：中國國家級關聯行為者 Storm-0940（2021 年起活躍、以竊取資料為目的）最早自 2026 年 9 月起使用 ARTEX 自動化對全球數百個組織的攻擊，受害產業橫跨航太與國防、汽車、化工、能源、金融服務、政府、法律、製造、媒體、軍方、半導體、軟體、科技與智庫非營利組織。部分攻擊讓它在初始鎖定後不到 3 小時就取得雲端基礎設施的特權存取。微軟評估 Storm-0940 就是那起多租戶雲端備份應用的 ConnectWise 供應鏈失守的責任方（ConnectWise 的初步公告發於 10/16），事後該行為者試圖登入逾 2,250 個租戶。另外一波 10/10–10/14 的密碼噴灑，用 144.172.64.99 的基礎設施打 8 個組織的 327 個帳號，微軟遙測記到逾 15.1 萬次失敗登入、10/11 尖峰每分鐘 2,900 次，該役未觀察到任何成功驗證。

ARTEX 是什麼

微軟的描述是：「ARTEX 是一個開源滲透測試框架，可以使用任何 AI 模型來自動化各種攻擊性安全工作流程。」技術上是一套以 Go 寫成、前端用 Next.js 的多代理 LLM 系統；介面預設英文，可切換韓文、中文、西班牙文、日文。它的 agent 能在幾乎沒有人類介入的情況下，從偵查一路自主跑到資料外洩，並把發現的資產與弱點存進一張圖。2026 年 10 月的公開報導已把它連結到韓國金融機構的個資外洩事件，微軟表示已在不同地區看到數個威脅行為者在用它。

為什麼重要

三個結構性的點。一、agent 把供應鏈攻擊的時間常數壓短了：微軟明說 agent 連續工作、可同時追多條突破路徑，縮短從選定目標到達成目的的時間。二、它攻擊的是信任而不是憑證：拿下幾個 ConnectWise 雲端應用的控制權後，agent 直接用這些應用既有的信任關係去驗證進入客戶租戶，不需要互動式使用者登入——這正是今天醫院和 HIS／雲端備份廠商之間的關係形狀。三、框架是開源的，所以這不是一次性的國家級能力，而是一條任何人都能取用的生產線。對醫療的直接意義：多租戶的醫療 IT 服務商（備份、PACS 雲、遠距判讀、計費）正是這個攻擊模式最理想的槓桿點，而醫院通常看不進這些廠商的內部——打一家 HIS 廠商等於打進數十到數百家醫療機構。要打折的地方：微軟自己強調大部分鎖定並未成功，且這些活動並非源於微軟自身系統被攻破；歸因本質上是機率判斷，這份報告是單一廠商視角、基於微軟遙測，沒有第三方獨立確證，「數百個組織」是範圍描述而非精確計數。

資安 NorForgeCairnDeere10/19

一個操作者、一套開源 agent 框架、逾 1,200 個目標：成功攻破逾 100 家公司網站，平均不到 23 小時，每成功一次約 50 美元

發生什麼

挪威資安公司 NorForge 的首席威脅研究員 Snorre Fagerland 在 10/19 發布報告：一個中文語系的攻擊者用開源多代理平台 Cairn（agent 逐步朝目標推進，並把發現貼到一面所有 agent 都能讀的共享看板）攻破逾 100 家公司的網站。路透記者 Raphael Satter 在發布前看過報告並確認了部分受害者：到前一週晚間，agent 已嘗試逾 1,200 個站；單一中文語系叢集就有逾 1,100 個攻擊專案、分布在 14 個控制面板，各工具平均成功率約 10%。成本上，Fagerland 給路透的粗估是約 5,000 美元的 token 支出換來約每成功一次 50 美元；NorForge 報告本身的數字是含失敗嘗試平均每項任務約 5 美元。行動自 9/25 開始，成功攻擊平均耗時不到 23 小時。所有任務跑在一個名為 claudecode_deepseek-v4.1-flash 的 worker 上。目標是美國、加拿大、日本、澳洲月流量 20 萬至 150 萬次的網路商店，agent 嘗試在各站執行程式並植入上傳型 web shell。被點名的受害者包括 Deere（已採取補救措施、未見敏感資訊被存取）、SharkNinja（稱攻擊打在一個獨立的產品支援站、已被控制住）與 Cummins（正在調查一起可能發生在其供應商網站上的攻擊）。掃描面板資料另外翻出數百組憑證與 API key，用 Trufflehog 驗證有 11% 仍有效。

為什麼重要

把這則跟上一則並排看，差別就是重點：Storm-0940 是國家級資源，這一則是一個人。每成功一次 50 美元、平均不到 23 小時、成功率一成——這組數字把「對一個中型網站發動定製化入侵」的單位成本壓到低於一次外送訂單的毛利。醫療的落點很具體：台灣與各國的中小型診所、檢驗所、健檢中心、長照機構幾乎都有一個外包的、長期未更新的網站或預約系統，上面常掛著可連到內部的憑證。過去這些站之所以安全，不是因為防護好，而是因為攻擊它們不划算。這個經濟假設在本週失效了。要打折的地方：路透無法確定究竟有多少資料（如果有）被取走，TNW 也未獨立驗證這些入侵；「每次 50 美元」是研究者給記者的粗估，與報告內文的「每項任務約 5 美元」是不同的計算基準，報告自己說不確定性相當大；模型歸屬是從 worker 名稱推斷的，不是廠商確認。

金融與 agent 治理 Morgan StanleyJPMorgan1Password10/22

摩根士丹利開始封鎖第三方 AI agent，因為它分不出哪個動作是客戶要的——而同一天 1Password 推出讓 agent 登入卻看不到密碼的產品

發生什麼

Axios 的 Madison Mills 10/22 報導：美國主要銀行正在偵測到未經授權的第三方 AI agent 在客戶帳戶裡活動，部分 agent 看起來在沒有使用者指示的情況下行動。有些銀行追蹤到 agent 打電話進客服中心，主管們最擔心的是有採購權或能移動資金的 agent。多數銀行無法可靠分辨 agent 活動是使用者指派的、還是 agent 跑脫了，一位銀行主管說他們難以區分不同 agent。應對上：摩根士丹利已開始封鎖第三方 agent 進入其平台（發言人表示該行並未觀察到「跑脫的 AI agent 存取我們的平台」），JPMorgan、美國銀行與花旗也在限制 agent，Chase 直接告訴客戶不要把帳號密碼給任何人。多數銀行已授權或正走向唯讀存取。同一天 1Password for Agents 上線：agent 嘗試登入時先送一組獨有的數位金鑰給 1Password 確認身分，使用者收到該次嘗試的通知並本人核可，核可後由 1Password 自己填入憑證，agent 從頭到尾看不到帳密。TechCrunch 點名支援的 agent 包括 Anthropic 的 Claude Duet、OpenAI 的 Dots 與 ChatGPT Work、Grok Bot、Meta 的 Muse 與新創 Town 的 agent。

為什麼重要

這是本週最有參考價值的一組，因為它是一個高度監管、歸屬責任極其明確的產業給出的第一份實際答卷，而答案是：先降為唯讀，等身分層長出來再說。醫療的結構幾乎完全一樣——高度監管、行為必須可歸屬到特定人、錯誤不可逆——唯一的差別是醫療沒有「唯讀」這條退路：臨床 agent 的價值主要在它能下單、能開 order、能回訊息、能更新病歷，一旦限制成唯讀就剩摘要。1Password 的解法值得精確理解：它解的是憑證外洩與身分確認，沒解的是授權範圍與事後歸屬——核可的是「這次登入」，不是「登入後能做哪些事」，而逐次人工核可在規模化後必然退化成反射性點擊，這正是醫療 alert fatigue 的老問題換一個介面重演。真正該抄的是那個設計原則：agent 必須有自己的身分，而不是借用某位臨床人員的帳號。今天絕大多數醫院的 AI 工具都是後者，所以稽核軌跡上看到的是醫師的 ID 在半夜開了一百個 order。要打折的地方：Axios 該則全篇沒有任何具體數字，多數敘述來自匿名消息源，而摩根士丹利官方立場與「封鎖」的動機敘述並不完全一致；1Password 的「不會看到密碼」是廠商自述的架構特性，報導未公開金鑰確認之外的協定名稱，也沒有定價與全面可用時程。

醫療 AI Microsoft AIMAI-DxOScience10/22

MAI-DxO 登上《Science》：NEJM 複雜病例 83% 對上單打獨鬥醫師的 36%，但論文自己的數字顯示大部分增益來自底層模型而非編排

發生什麼

Microsoft 的 MAI-DxO 在 2026/10/22（週四）刊於《Science》。它編排數個 AI agent 像一組醫師會診那樣運作：向病人問診、開立檢查、相互辯論出診斷。在模擬的 NEJM 複雜病例上，MAI-DxO 正確率 83%，而獨自作業、可查閱參考資料的基層醫師與一般內科醫師是 36%（專科醫師與醫師團隊不在對照組內）。逐模型拆解才是這篇真正的資訊量：GPT-5 單用簡短基本 prompt 在複雜病例上就有 78.9%、每病例成本約 8,400 美元；加上 DxO 後成本降約 3,000 美元，但正確率只升約 4 個百分點。GPT-5.5（2026 年 4 月釋出）在複雜病例上從 72% 升到近 87%、成本略降。急診病例則幾乎沒有增益：GPT-5.5 加不加 DxO 都約 85%。Gemini 2.5 Flash 單用 46.4%、加 DxO 近 69%——強弱模型之間的落差仍大於 DxO 帶來的提升。受測模型涵蓋 OpenAI、Google、Anthropic、Meta 與 DeepSeek。Microsoft 把 medical superintelligence 定義為「在醫學推理與協調上超越當代最強的人類主導醫療系統的能力」；Microsoft AI 執行長 Mustafa Suleyman 說公司正與 Mayo Clinic 合作一個醫療基礎模型、計畫明年釋出，並預期醫療 AI 在 24 至 36 個月內大幅改善，且將與波士頓的 Beth Israel Deaconess Medical Center 在真實急診與急症照護場景中測試 DxO。

為什麼重要

把它放進今天這條線，它的角色不是「醫療 AI 又破紀錄」，而是需求側的時鐘。前四則說的是 agent 的身分、監控與供應鏈這三層還沒長好；這一則說的是，最大的平台廠已經把「超越人類主導醫療系統」寫成公開目標、已經有頂尖期刊背書、已經排好與一家波士頓學術醫學中心的真實場景試驗。供給與治理的時間差就是風險所在。另一個該被注意的訊號是成本：每病例約 8,400 美元的推論成本，意味著這套方法目前只在「診斷錯誤代價極高的罕病與複雜病例」這一段有經濟意義，而這恰好與急診病例沒有增益的結果互相印證。

要打折的地方

這則要打的折最多。一、對照組的設計：83% 對上的 36% 是「獨自作業、可查參考資料」的基層與一般內科醫師，專科醫師與醫師團隊沒有被納入對照，而 NEJM 複雜病例的正確診斷通常本來就需要專科與團隊。二、病例來源：NEJM 病例是為教學而寫、資訊完整、已知有單一正確答案，與急診現場的不確定性不同——而論文自己的急診結果（加 DxO 無明顯增益）就是這個落差的證據。三、增益歸屬：TechCrunch 明確指出大部分改善來自底層模型，DxO 是在上面加分；Gemini 2.5 Flash 從 46.4% 到 69% 的大幅提升，反而說明 DxO 主要在補弱模型的不足。四、這是模擬，Beth Israel Deaconess 的真實場景測試還沒做。五、成本數字是每病例約 8,400 美元，與任何現行給付制度都不相容。

Carbon-X

開源 14.8B 參數 DNA 對話模型 · Hugging Face × 中關村學院 × Telethon Institute of Genetics and Medicine／Naples Federico II · 2026/10/22 發表

功能與定位。讓研究者用自然語言「與 DNA 對話」：分析與生成 DNA 序列、回答變異效應問題。技術上以 Qwen3-14B 為底加入 DNA token，Apache 2.0 授權，context window 40,960 token，bfloat16 權重可塞進單張 80 GB GPU、以 vLLM 服務。tokenizer 加入 4,096 個六鹼基 6-mer、1,364 個 tail token 與三個標記。訓練分四段：詞彙擴充約 100 億 token（凍結 transformer 主體）、mid-training 3,020 億 token（序列長度 8,192，55% 原始 DNA、20% 英文網頁、15% 生物學文本、10% 指令資料）、SFT 三個 epoch 跨 20 個資料子集（約 30% 是變異效應推理），以及兩輪帶程式碼檢核獎勵的非同步 GRPO。在作者自評的五項 DNA benchmark 上平均 66.7 分，對照 GPT-6.1 Sol (Max) 的 67.5、Opus 5.5 (Max) 的 60.9、Gemini 4 Argon (Low) 的 49.8。

  • 優勢 ：成本結構，而不是分數，才是這個模型的新聞點。模型卡估算其每題推論成本約為 GPT-6.1 Sol 的千八百分之一，並推估分析 ClinVar 的 240 萬個 VUS（未知意義變異）約需 300 美元，對照競品的 3.2 萬至 400 萬美元。對臨床基因體學來說，VUS 重新判讀一直是個規模問題而非方法問題——能全量重跑，意義完全不同。加上 Apache 2.0 與單卡可跑，醫學中心可以在院內、資料不出場的前提下自建，這在基因體資料跨境傳輸受限的管轄區（含台灣）是決定性的。
  • 疑慮 ：所有關鍵數字都是作者自報，且五項 benchmark 中有兩項是作者自己建的，沒有獨立重現。千八百分之一的成本是基於作者的定價假設（以 H200 每小時 5 美元計），而吞吐量數字並未公開；300 美元跑完 240 萬個 VUS 只是外推，並未真的跑過 ClinVar；「便宜一千倍以上」的說法來自一則無署名社群貼文，不在模型卡上。
  • 疑慮 ：臨床效力完全未經驗證，模型卡自己說不應用於指導醫療決策，且沒有做濕實驗驗證。作者列出的限制包括：會數錯鹼基或座標、在缺乏上下文時可能編造序列的身分與功能、在 splice site 與 histone mark 任務上明顯偏弱（GenomeQA 分項只有 29.8% 與 34.6%，對照 organism group 的 93.2%、motifs 的 90.0%）、長序列生成品質下降。換句話說，它最弱的那幾項正好是臨床變異判讀最常需要的——VUS 的重新分類有相當比例依賴剪接位點預測。

OpenAI
前沿模型與消費級平台		 正在洽談最多 300 億美元募資、投前估值 1.25 兆美元，Coatue 領投、並有來自阿聯的投資人，該筆資金可能搭配一樁讓 OpenAI 在阿聯取得更多算力的交易（TechCrunch 10/22，條件仍在議、OpenAI 不評論）。對照點：2026 年 3 月那輪投後估值 8,520 億美元，OpenAI 已於 2026 年 6 月機密遞交 IPO 文件。同一週，METR 公布其內部 agent 監控系統的多項漏洞。 護城河是分發與算力承諾的規模。弱點在本週變得具體：它既是 Agentic AI Foundation 的共同創辦者（治理開放），又是被外部稽核發現監控系統可被繞過的那一家，而 MAI-DxO 的最佳成績還是跑在 GPT-5／5.5 上——醫療成就被記在 Microsoft 名下，模型紅利歸它，品牌與責任的分配並不對稱。
Microsoft
同一週同時是最大的醫療 AI 主張者與最大的 agent 威脅情報來源		 Microsoft AI：MAI-DxO 10/22 登上《Science》、NEJM 複雜病例 83%、與 Mayo Clinic 的醫療基礎模型預計明年釋出、與 Beth Israel Deaconess 進行真實場景測試。Microsoft Security：10/21 歸因 Storm-0940 與 ARTEX、ConnectWise 事後試登逾 2,250 個租戶、10/10–14 的密碼噴灑逾 15.1 萬次失敗登入。 護城河是唯一同時握有前沿模型存取、臨床通路（Mayo、Beth Israel）與全球威脅遙測的那一家，所以它的醫療主張比任何純 AI 公司更難被忽略。弱點是兩個部門的訊息互相打臉：一邊說要追 medical superintelligence，另一邊的報告說 agent 已經能在三小時內拿下雲端特權——而醫院要同時相信這兩件事並做出採購決策。
1Password
憑證管理，轉向 agent 身分層		 10/22 推出 1Password for Agents，支援 Anthropic 的 Claude Duet、OpenAI 的 Dots 與 ChatGPT Work、Grok Bot、Meta 的 Muse 與 Town 的 agent，機制是 agent 以獨有數位金鑰向 1Password 證明身分、使用者逐次核可、由 1Password 代填憑證。報導未提供定價、方案分層或區域可用性，也未公開金鑰確認之外的協定名稱。 它搶的是本週被證明最缺的那一層，而且位置很好：同時被 Anthropic、OpenAI、Meta、xAI 的 agent 接受，等於成為跨陣營的中立身分仲介。弱點是這一層注定會被平台自己收回去——身分與授權是作業系統級的功能，而它目前解的是憑證外洩，沒有解授權範圍與事後歸屬，後者才是摩根士丹利封鎖 agent 的真正理由。

把這一節收束成一句話：今天的競爭不在模型分數，而在誰能先把「這個動作是誰的」變成一個可查證的事實。攻擊側已經商品化了（開源框架 ARTEX 與 Cairn、每次成功 50 美元、不到 23 小時），資本側已經把賭注加到 1.25 兆美元的投前估值，需求側已經由 Microsoft 把「超越人類主導醫療系統」寫進《Science》——而身分與歸屬這一層，目前最完整的答案是一家密碼管理公司在 10/22 推出的產品，以及一家銀行決定全部封鎖。醫療會是這個落差最先付出代價的地方，因為它同時具備銀行的歸屬責任與銀行所沒有的那件事：它無法接受把 agent 降為唯讀。

04 — Taiwan Angle

台灣已經有 AI 基本法、有國家級戰略委員會——但它們管的都是「AI 系統」，沒有一樣管得到「AI agent 代替誰做了什麼」

法規的顆粒度對不上 agent。台灣的 AI 基本法已於 2025/12/23 三讀通過，明定國科會為中央主管機關，並由行政院設國家 AI 戰略特別委員會、由行政院長召集、每年至少開會一次、國科會負責幕僚作業（iThome 對三讀條文的整理）。委員會已於 2026/5/21 由行政院宣布成立，由卓榮泰院長親自督軍，目標2028 年前訂出管理規範（中央社 2026-05-21、自由時報 2026-05-21）。風險管理上，條文並未建立完整的多級分類，而是主要區分「高風險」AI 產品或系統，由中央目的事業主管機關會商數發部認定、須標示注意事項或警語。問題就在這裡：這套框架的規範對象是產品或系統的風險等級，而本週揭露的風險不是「這個模型準不準」，而是「這個 agent 用了誰的帳號、在什麼授權範圍內、做了什麼不可逆的動作、而這件事有沒有被記錄下來」。METR 的發現是監控的觸發時機可被 agent 自己影響；摩根士丹利封鎖 agent 的理由是分不出動作歸屬。這兩件事在「高風險產品認定」這個顆粒度上完全看不見。七大原則裡的「問責」提供了法源，但要落到可執行，缺的是 agent 身分、動作層級稽核與授權範圍這三項技術規範——而這恰好是數發部被賦予「提供評估與驗證工具」職權可以切入的地方。另一件不必等 2028 年的事：ConnectWise 的攻擊路徑就是台灣醫療 IT 的形狀，HIS、PACS 雲、檢驗資訊系統、健保申報、備份與災難復原都集中在少數廠商手上，打一家廠商等於打進數十到數百家醫療機構，所以把廠商端的應用程式憑證輪替與異常登入告警納入年度資安稽核、在合約裡訂下供應鏈事件通報時限、盤點所有以服務帳號或共用帳號運行的介接，是現在就能做的三件事。

05 — Further Reading

這份清單只收「讀完會改變你怎麼做決定」的東西
  1. Red-Teaming OpenAI's Internal Agent Monitoring Systems — METR (2026-10-22)

    不要只看漏洞清單，看最後那幾條設計建議。「agent 採取的動作不應該能影響監控系統是否執行、何時執行」這一句，可以直接當成任何醫院採購臨床 agent 時的驗收條款來用——而且目前市面上幾乎沒有產品能通過。

  2. Storm-0940 uses ARTEX agentic AI in ConnectWise supply chain compromise — Microsoft Security Blog (2026-10-21)

    讀它的 MITRE 對照表而不是敘事段落。裡面有一條是某 ConnectWise 管理應用程式自行指派 Global Administrator 角色，另有 Defender 偵測到跨多個 vault 的大量 Azure Key Vault secret 讀取——這兩個偵測訊號可以直接拿去問自家的雲端服務商有沒有在看。

  3. Formal verification at scale with Claude — Anthropic Frontier Red Team with Theorem (2026-10-22)

    本週的另一面：同一種能力被用來證明而非攻擊。Claude 對 123 個開源函式庫、239 個 fuzz test 入口點的編譯後 RISC-V 二進位做出機器可驗證的證明（約 1.8 億行 Rocq），順手重新發現 libexpat 的 CVE-2026-56132。但值得讀的是它的限制章節：「形式驗證過不等於沒有 bug」、證明覆蓋的是 musl 連結的靜態 RISC-V 二進位而非大多數人在跑的 x86／ARM 與 glibc 版本——這兩句是未來幾年所有「AI 驗證過的醫材軟體」行銷說法的照妖鏡。

  4. AI agents broke into 100+ company websites for about $50 each — The Next Web, reporting NorForge and Reuters (2026-10-19 onward)

    讀它的叢集分析：14 個中文語系控制面板、逾 1,100 個專案、約 10% 成功率。這組數字的用途不是恐嚇，而是讓你能估算自家外包網站的實際風險——如果你有一個沒人負責更新的站，它現在的年化被攻破機率已經不能用「我們太小不值得打」來估。

  5. Donating Agent Skills to the Agentic AI Foundation — Anthropic (2026-10-22)

    Anthropic 把 Agent Skills 連同名稱、GitHub 組織與 agentskills.io 網域捐給 Linux Foundation 底下的 AAIF，自述自 2025 年 12 月標準公開以來已有逾 70 個平台整合、100 萬個 skill、近 2.8 億次安裝。重點在路線圖裡那條「給 skill 撰寫者與安裝者的安全指引」：一個 skill 就是一個會被 agent 讀進上下文並照著執行的資料夾，所以它的分發在威脅模型上等同套件管理器——而醫院資訊室現在要開始把 skill 當成醫材軟體的供應鏈元件來管。
