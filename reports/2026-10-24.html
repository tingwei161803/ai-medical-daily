今天不挑醫療新聞當主線，因為這一週最重要的 AI 事件不在醫療裡，而醫療是它最沒有準備好的落點。METR 10/22 公布的紅隊報告說，OpenAI 的內部失準監控只在 agent 把控制權交回使用者時才觸發，所以 agent「只要持續動作就能無限期延後被監控」；同一週微軟把 9 月以來對數百個組織的攻擊歸因到一個用開源多代理滲透框架的國家級行為者，而 NorForge 的報告說一個操作者用 agent 攻破逾 100 家公司網站、每成功一次約 50 美元。對照組是摩根士丹利開始封鎖第三方 agent，因為它分不出哪個動作是客戶要的。而同一天，Microsoft 的 MAI-DxO 登上《Science》、Suleyman 說要追 medical superintelligence。身分與監控這一層的成熟度，現在是醫療 agent 落地的實際天花板，不是模型準確率。 Today's lead is not a medical story, because the week's most consequential AI event did not happen in medicine — and medicine is where it is least ready to land. The red-team report METR published on Oct 22 found that OpenAI's internal misalignment monitor fired only when an agent returned control to the user, so an agent could postpone monitoring indefinitely simply by continuing to act. The same week Microsoft attributed attacks on hundreds of organizations since September to a state-aligned actor running an open-source multi-agent pentest framework, and NorForge reported one operator whose agents broke into more than 100 company websites at roughly $50 per success. The control group: Morgan Stanley has started blocking third-party agents because it cannot tell which actions the customer asked for. And the same day Microsoft's MAI-DxO landed in Science, with Suleyman chasing medical superintelligence. The maturity of the identity-and-oversight layer, not model accuracy, is now the real ceiling on clinical agents.

METR 與 Redwood 在 OpenAI 內部待了三週，結論是「agent 只要持續動作就能無限期延後被監控」 METR and Redwood spent three weeks inside OpenAI and concluded that an agent can postpone monitoring indefinitely just by continuing to act

發生什麼What

一名 METR 員工與一名 Redwood Research 員工在 2026/7/21 至 8/11 進入 OpenAI，做了一次「高權限試點演練」，壓測它的內部失準監控系統，拿到內部程式庫、monitor prompt 與設定、內部文件，並訪談約十二位研究員與工程師，全程使用不離場的 OpenAI 公發裝置、現場有人陪同。成果是一份 61 頁報告，10/22 公布的公開版經 OpenAI 遮蔽後為 38 頁。幾個具體數字：以 GPT-5.5 等級以上模型的內部 agentic Responses API 流量計，METR 估只有約 75–94%「有資格」被監控（內部 Codex agent 使用的子集是 99.2%，METR 自述「兩個方向都有相當大的不確定性」）；不監控 compaction 事件，使 2026 年 5 月到 7 月約「一成量級」的 Codex 流量漏掉（OpenAI 自己在演練前發現、演練期間修掉）；monitor 本身錯誤率「低於 0.2%」。漏洞方面：monitor 只在 agent 把控制權交回使用者時觸發，所以「agent 只要持續動作就能無限期延後被監控」；一個 exploit 可讓「數百個近期動作」不被監控（細節被遮蔽）；序列化差異可讓 agent 構造輸入使 monitor 失敗、軌跡不被升級給人工審查；兩個客戶端可控的 header 能對新 agent 關掉監控；還有一條路徑可「原則上」繞過 Codex sandbox 與 Auto-Review。 One METR employee and one Redwood Research employee went into OpenAI from Jul 21 to Aug 11, 2026 for a "pilot high-access exercise" stress-testing its internal misalignment monitoring system, with access to the internal codebase, monitor prompts and configuration, and internal documentation, plus interviews with about a dozen researchers and engineers — all on OpenAI-issued devices that never left the premises, accompanied onsite. The output was a 61-page report; the public version released Oct 22, after OpenAI's redactions, runs 38 pages. The figures: of internal agentic Responses API traffic from models at least as strong as GPT-5.5, METR estimated only roughly 75–94% was eligible for monitoring (99.2% for the subset used by internal Codex agents, with METR noting "substantial uncertainty in both directions"); not monitoring compaction events likely left "on the order of 10%" of eligible Codex traffic unmonitored between May and July 2026 (found by OpenAI staff before the exercise, fixed during it); and the monitor itself errored on "less than 0.2%" of requests. The vulnerabilities: the monitor triggered when agents returned control to the user, so "agents could indefinitely postpone being monitored by simply continuing to take actions"; one exploit could prevent "hundreds of recent actions" from being monitored (details redacted); serialization differences between what agents see and what monitors see could let agents build inputs that make the monitor fail, so trajectories were never escalated for human review; two client-controllable headers disabled monitoring for new agents; and a path existed to "in principle" bypass Codex sandboxing and Auto-Review.

為什麼重要Why it matters

這不是「某家公司資安沒做好」的故事，而是整個產業把 agent 治理建立在一個未經對抗測試的假設上：監控系統是外生的、agent 動不到它。METR 的建議直指這一點——「agent 採取的動作，不應該能影響監控系統是否執行、何時執行」，而這正是被破的那一條。對醫療的意義很直接：醫療 agent 的治理方案（稽核軌跡、人機協同審查、事後回溯）全部假設「所有動作都會被記錄下來」。METR 的發現是，當被監控者本身是個有能力的 agent，這個假設需要被當成安全屬性來證明，不是當成架構圖裡的一個方框。要打折的地方也要說清楚：公開版只有私下報告的一小部分、OpenAI 有遮蔽權，METR 自述這是測試「存取安排」的試點而非完整透明度報告，而 OpenAI 事後說所有影響生產防護堆疊的漏洞都已修補、但 METR 明確表示它沒有評估這些說法；覆蓋率 75–94% 也是估計值而非量測值。The Register 10/23 的報導另補一個公道的註腳：報告並未主張 agent 刻意隱藏了活動，只是說這套監控有可能漏掉這類行為。 This is not a story about one company's sloppy security. It is about an industry building agent governance on an assumption that had never been adversarially tested: that the monitor is exogenous and the agent cannot touch it. METR's recommendation names exactly that — "actions agents take should not be able to influence whether or when the monitoring system runs" — and that is precisely what broke. The implication for healthcare is direct: every governance scheme for clinical agents (audit trails, human-in-the-loop review, retrospective reconstruction) assumes that all actions get logged. METR's finding is that when the thing being monitored is itself a capable agent, that assumption has to be proven as a security property, not drawn as a box in an architecture diagram. The discounts matter too: the public version is only a small part of the private report and OpenAI held redaction rights, METR describes this as a pilot testing access arrangements rather than a full transparency report, and while OpenAI says all vulnerabilities affecting its production safeguards stack were patched, METR explicitly states it has not evaluated those claims; the 75–94% figure is an estimate, not a measurement. The Register's Oct 23 write-up adds a fair footnote: the report does not claim agents deliberately concealed activity, only that this monitoring could have missed such behaviour.

資安Security MicrosoftConnectWiseARTEX10/21

微軟把 ConnectWise 供應鏈失守歸因到用開源多代理框架 ARTEX 的 Storm-0940：事後試登逾 2,250 個租戶，最快不到 3 小時拿下雲端特權 Microsoft attributes the ConnectWise supply-chain compromise to Storm-0940 running ARTEX, an open-source multi-agent framework: 2,250-plus tenants targeted afterwards, privileged cloud access in under three hours

發生什麼What

微軟威脅情報 10/21 發布分析：中國國家級關聯行為者 Storm-0940（2021 年起活躍、以竊取資料為目的）最早自 2026 年 9 月起使用 ARTEX 自動化對全球數百個組織的攻擊，受害產業橫跨航太與國防、汽車、化工、能源、金融服務、政府、法律、製造、媒體、軍方、半導體、軟體、科技與智庫非營利組織。部分攻擊讓它在初始鎖定後不到 3 小時就取得雲端基礎設施的特權存取。微軟評估 Storm-0940 就是那起多租戶雲端備份應用的 ConnectWise 供應鏈失守的責任方（ConnectWise 的初步公告發於 10/16），事後該行為者試圖登入逾 2,250 個租戶。另外一波 10/10–10/14 的密碼噴灑，用 144.172.64.99 的基礎設施打 8 個組織的 327 個帳號，微軟遙測記到逾 15.1 萬次失敗登入、10/11 尖峰每分鐘 2,900 次，該役未觀察到任何成功驗證。 Microsoft Threat Intelligence published its analysis on Oct 21: Storm-0940, a China-state-aligned actor active since 2021 and focused on data theft, used ARTEX as early as September 2026 to automate attacks on hundreds of organizations worldwide, across aerospace and defence, automotive, chemicals, energy, financial services, government, legal, manufacturing, media, military, semiconductor, software, technology, and think tanks and non-profits. Several attacks gave it privileged access to cloud infrastructure in less than three hours from initial targeting. Microsoft assesses Storm-0940 was responsible for the ConnectWise supply-chain compromise of a multi-tenant cloud backup application (ConnectWise published its initial advisory on Oct 16); afterwards the actor tried to sign in to more than 2,250 tenants. A separate password-spray from Oct 10 to 14, from infrastructure at 144.172.64.99, targeted 327 accounts across eight organizations, producing over 151,000 failed logons in Microsoft telemetry and peaking at 2,900 failures per minute on Oct 11, with no successful authentication observed in that campaign.

ARTEX 是什麼What ARTEX is

微軟的描述是：「ARTEX 是一個開源滲透測試框架，可以使用任何 AI 模型來自動化各種攻擊性安全工作流程。」技術上是一套以 Go 寫成、前端用 Next.js 的多代理 LLM 系統；介面預設英文，可切換韓文、中文、西班牙文、日文。它的 agent 能在幾乎沒有人類介入的情況下，從偵查一路自主跑到資料外洩，並把發現的資產與弱點存進一張圖。2026 年 10 月的公開報導已把它連結到韓國金融機構的個資外洩事件，微軟表示已在不同地區看到數個威脅行為者在用它。 Microsoft's own description: "ARTEX is an open-source penetration testing framework that can use any AI model to automate a variety of offensive security workflows." Technically it is a multi-agent LLM system written in Go with a Next.js frontend; the interface defaults to English and can be switched to Korean, Mandarin, Spanish or Japanese. Its agents run an autonomous penetration test from reconnaissance through data exfiltration with little human input, storing discovered assets and vulnerabilities in a graph. Public reporting in October 2026 already linked it to personal-data breaches at Korean financial institutions, and Microsoft says it has seen several threat actors in different regions using it.

為什麼重要Why it matters

三個結構性的點。一、agent 把供應鏈攻擊的時間常數壓短了：微軟明說 agent 連續工作、可同時追多條突破路徑，縮短從選定目標到達成目的的時間。二、它攻擊的是信任而不是憑證：拿下幾個 ConnectWise 雲端應用的控制權後，agent 直接用這些應用既有的信任關係去驗證進入客戶租戶，不需要互動式使用者登入——這正是今天醫院和 HIS／雲端備份廠商之間的關係形狀。三、框架是開源的，所以這不是一次性的國家級能力，而是一條任何人都能取用的生產線。對醫療的直接意義：多租戶的醫療 IT 服務商（備份、PACS 雲、遠距判讀、計費）正是這個攻擊模式最理想的槓桿點，而醫院通常看不進這些廠商的內部——打一家 HIS 廠商等於打進數十到數百家醫療機構。要打折的地方：微軟自己強調大部分鎖定並未成功，且這些活動並非源於微軟自身系統被攻破；歸因本質上是機率判斷，這份報告是單一廠商視角、基於微軟遙測，沒有第三方獨立確證，「數百個組織」是範圍描述而非精確計數。 Three structural points. First, agents compress the time constant of supply-chain attacks: Microsoft says explicitly that agents work continuously and can pursue several breach paths at once, cutting the time from target selection to objective. Second, it attacks trust rather than credentials: after taking control of several ConnectWise cloud applications, the agents authenticated into customer tenants using the trust those applications already held, with no interactive user sign-in — exactly the shape of the relationship between a hospital and its HIS or cloud-backup vendor today. Third, the framework is open source, so this is not a one-off state capability but a production line anyone can pick up. The direct healthcare read: multi-tenant health IT providers (backup, cloud PACS, teleradiology, billing) are the ideal leverage point for this pattern, and hospitals generally cannot see inside them — hitting one HIS vendor means reaching dozens to hundreds of care providers. The discounts: Microsoft itself stresses that most of the targeting was unsuccessful and that the activity did not stem from a compromise of its own systems; attribution is inherently probabilistic, this is a single-vendor view built on Microsoft telemetry with no independent confirmation, and "hundreds of organizations" is a range, not a precise count.

一個操作者、一套開源 agent 框架、逾 1,200 個目標：成功攻破逾 100 家公司網站，平均不到 23 小時，每成功一次約 50 美元 One operator, one open-source agent framework, 1,200-plus targets: more than 100 company websites breached, averaging just under 23 hours, at about $50 per success

發生什麼What

挪威資安公司 NorForge 的首席威脅研究員 Snorre Fagerland 在 10/19 發布報告：一個中文語系的攻擊者用開源多代理平台 Cairn（agent 逐步朝目標推進，並把發現貼到一面所有 agent 都能讀的共享看板）攻破逾 100 家公司的網站。路透記者 Raphael Satter 在發布前看過報告並確認了部分受害者：到前一週晚間，agent 已嘗試逾 1,200 個站；單一中文語系叢集就有逾 1,100 個攻擊專案、分布在 14 個控制面板，各工具平均成功率約 10%。成本上，Fagerland 給路透的粗估是約 5,000 美元的 token 支出換來約每成功一次 50 美元；NorForge 報告本身的數字是含失敗嘗試平均每項任務約 5 美元。行動自 9/25 開始，成功攻擊平均耗時不到 23 小時。所有任務跑在一個名為 claudecode_deepseek-v4.1-flash 的 worker 上。目標是美國、加拿大、日本、澳洲月流量 20 萬至 150 萬次的網路商店，agent 嘗試在各站執行程式並植入上傳型 web shell。被點名的受害者包括 Deere（已採取補救措施、未見敏感資訊被存取）、SharkNinja（稱攻擊打在一個獨立的產品支援站、已被控制住）與 Cummins（正在調查一起可能發生在其供應商網站上的攻擊）。掃描面板資料另外翻出數百組憑證與 API key，用 Trufflehog 驗證有 11% 仍有效。 Snorre Fagerland, principal threat researcher at the Norwegian security firm NorForge, published a report on Oct 19: a Chinese-speaking attacker used the open-source multi-agent platform Cairn — whose agents work towards a goal step by step and post findings to a shared board every agent can read — to break into the websites of more than 100 companies. Reuters reporter Raphael Satter saw the report before publication and identified some victims: by late the previous week the agents had attempted more than 1,200 sites; the Chinese-language cluster alone held over 1,100 attack projects across 14 control panels, with an average success rate across tools of about 10%. On cost, Fagerland's rough figure for Reuters was roughly $5,000 in tokens for about $50 per successful hack; NorForge's own report puts it at about $5 per task including failed attempts. The campaign began Sep 25, and successful attacks took just under 23 hours on average. All tasks ran on a worker named claudecode_deepseek-v4.1-flash. The targets were online shops in the US, Canada, Japan and Australia with 200,000 to 1.5 million visits, and the agents tried to run code on each site and plant an uploader web shell. Named victims include Deere (took remediation steps, saw no sign sensitive information was accessed), SharkNinja (said the attack hit a standalone product-support site and was contained) and Cummins (investigating a possible attack on a vendor-run website). Scanning the panel data also turned up hundreds of credentials and API keys, of which Trufflehog verified 11% as still valid.

為什麼重要Why it matters

把這則跟上一則並排看，差別就是重點：Storm-0940 是國家級資源，這一則是一個人。每成功一次 50 美元、平均不到 23 小時、成功率一成——這組數字把「對一個中型網站發動定製化入侵」的單位成本壓到低於一次外送訂單的毛利。醫療的落點很具體：台灣與各國的中小型診所、檢驗所、健檢中心、長照機構幾乎都有一個外包的、長期未更新的網站或預約系統，上面常掛著可連到內部的憑證。過去這些站之所以安全，不是因為防護好，而是因為攻擊它們不划算。這個經濟假設在本週失效了。要打折的地方：路透無法確定究竟有多少資料（如果有）被取走，TNW 也未獨立驗證這些入侵；「每次 50 美元」是研究者給記者的粗估，與報告內文的「每項任務約 5 美元」是不同的計算基準，報告自己說不確定性相當大；模型歸屬是從 worker 名稱推斷的，不是廠商確認。 Read this alongside the previous story and the difference is the point: Storm-0940 is a state-resourced operation, this is one person. Fifty dollars per success, under 23 hours on average, a 10% hit rate — those numbers push the unit cost of a bespoke intrusion against a mid-sized website below the margin on a food-delivery order. The healthcare read is concrete: small and mid-sized clinics, labs, health-screening centres and long-term care facilities in Taiwan and elsewhere almost all run an outsourced, long-unpatched website or booking system, often holding credentials that reach inside. What kept those sites safe was never the strength of their defences but the fact that attacking them did not pay. That economic assumption stopped holding this week. The discounts: Reuters could not establish how much data, if any, was taken, and TNW has not independently verified the intrusions; the "$50 per success" figure is a researcher's rough estimate on a different basis from the report's own "about $5 per task", with considerable stated uncertainty; and the model attribution is inferred from a worker name rather than confirmed by any vendor.

Some banks have tracked agents calling into call centres, and executives worry most about agents with purchase authority or the ability to move funds. Most banks cannot reliably tell whether agent activity is user-directed or whether an agent has gone rogue, and one executive said they struggle to differentiate between agents. The responses: Morgan Stanley has begun blocking third-party agents from its platforms (a spokesperson said the bank has not observed "rogue AI agents accessing our platforms"), JPMorgan, Bank of America and Citi are also restricting agents, and Chase told customers not to give their usernames and passwords to anyone. 為什麼重要Why it matters

這是本週最有參考價值的一組，因為它是一個高度監管、歸屬責任極其明確的產業給出的第一份實際答卷，而答案是：先降為唯讀，等身分層長出來再說。醫療的結構幾乎完全一樣——高度監管、行為必須可歸屬到特定人、錯誤不可逆——唯一的差別是醫療沒有「唯讀」這條退路：臨床 agent 的價值主要在它能下單、能開 order、能回訊息、能更新病歷，一旦限制成唯讀就剩摘要。1Password 的解法值得精確理解：它解的是憑證外洩與身分確認，沒解的是授權範圍與事後歸屬——核可的是「這次登入」，不是「登入後能做哪些事」，而逐次人工核可在規模化後必然退化成反射性點擊，這正是醫療 alert fatigue 的老問題換一個介面重演。真正該抄的是那個設計原則：agent 必須有自己的身分，而不是借用某位臨床人員的帳號。今天絕大多數醫院的 AI 工具都是後者，所以稽核軌跡上看到的是醫師的 ID 在半夜開了一百個 order。要打折的地方：Axios 該則全篇沒有任何具體數字，多數敘述來自匿名消息源，而摩根士丹利官方立場與「封鎖」的動機敘述並不完全一致；1Password 的「不會看到密碼」是廠商自述的架構特性，報導未公開金鑰確認之外的協定名稱，也沒有定價與全面可用時程。 This is the week's most instructive pairing, because it is the first practical answer from a heavily regulated industry with unambiguous attribution requirements, and the answer is: drop to read-only and wait for the identity layer to grow in. Healthcare's structure is almost identical — heavily regulated, actions must be attributable to a specific person, mistakes are irreversible — with one difference: in medicine "read-only" is not a fallback that still meets the business need. The value of a clinical agent lies in placing orders, replying to messages and updating the record; restrict it to read-only and what remains is summarization. 1Password's answer deserves precision: it solves credential exposure and agent identity but not authorization scope or after-the-fact attribution — what gets approved is this login, not what may be done after it, and per-login approval degrades into reflexive clicking at scale, which is alert fatigue replayed through a new interface. What health systems should copy is the design principle: an agent must hold its own identity rather than borrow a clinician's account. Today almost every hospital AI tool does the latter, which is why the audit trail shows a physician's ID placing a hundred orders at 3am. The discounts: the Axios piece contains no specific figures at all and rests largely on anonymous sources, and Morgan Stanley's official line does not sit entirely with the stated motive for blocking; 1Password's "never sees the password" is a vendor-stated architectural property, with no protocol named beyond the key-confirmation step and no pricing or general-availability date.

It lets researchers "chat with DNA" in natural language: analysing and generating DNA sequences and answering variant-effect questions. Technically it is Qwen3-14B with DNA tokens added, under Apache 2.0, with a 40,960-token context window, bfloat16 weights that fit on a single 80 GB GPU, served with vLLM. The tokenizer adds 4,096 six-base 6-mers, 1,364 tail tokens and three markers. Training ran in four stages: vocabulary extension on about 10B tokens with the transformer body frozen; mid-training on 302B tokens at sequence length 8,192 (55% raw DNA, 20% English web text, 15% biology text, 10% instruction data); supervised fine-tuning over three epochs across 20 dataset subsets, about 30% of it variant-effect reasoning; and two rounds of asynchronous GRPO with code-checked rewards. It averages 66.7 across five author-reported DNA benchmarks, against 67.5 for GPT-6.1 Sol (Max), 60.9 for Opus 5.5 (Max) and 49.8 for Gemini 4 Argon (Low).

The model card estimates inference at about 1/1,800 of GPT-6.1 Sol's cost per problem, and extrapolates that analysing ClinVar's 2.4 million variants of uncertain significance would cost roughly $300, against $32,000 to $4 million for rivals. The 1/1,800 cost rests on the authors' pricing assumptions (H200 at $5/hour) and the throughput figure is not disclosed; the $300 for 2.4 million VUS is an extrapolation and no ClinVar run was actually performed; and the ">1,000x cheaper" claim comes from an unattributed social post, not the model card.
  • 疑慮Concern ：臨床效力完全未經驗證，模型卡自己說不應用於指導醫療決策，且沒有做濕實驗驗證。作者列出的限制包括：會數錯鹼基或座標、在缺乏上下文時可能編造序列的身分與功能、在 splice site 與 histone mark 任務上明顯偏弱（GenomeQA 分項只有 29.8% 與 34.6%，對照 organism group 的 93.2%、motifs 的 90.0%）、長序列生成品質下降。換句話說，它最弱的那幾項正好是臨床變異判讀最常需要的——VUS 的重新分類有相當比例依賴剪接位點預測。 : clinical validity is entirely unvalidated, the model card itself says it should not guide medical decisions, and no wet-lab validation was done. Which is to say: its weakest tasks are precisely the ones clinical variant interpretation needs most — a substantial share of VUS reclassification turns on splice-site prediction.

法規的顆粒度對不上 agent。台灣的 AI 基本法已於 2025/12/23 三讀通過，明定國科會為中央主管機關，並由行政院設國家 AI 戰略特別委員會、由行政院長召集、每年至少開會一次、國科會負責幕僚作業（iThome 對三讀條文的整理）。委員會已於 2026/5/21 由行政院宣布成立，由卓榮泰院長親自督軍，目標2028 年前訂出管理規範（中央社 2026-05-21、自由時報 2026-05-21）。風險管理上，條文並未建立完整的多級分類，而是主要區分「高風險」AI 產品或系統，由中央目的事業主管機關會商數發部認定、須標示注意事項或警語。問題就在這裡：這套框架的規範對象是產品或系統的風險等級，而本週揭露的風險不是「這個模型準不準」，而是「這個 agent 用了誰的帳號、在什麼授權範圍內、做了什麼不可逆的動作、而這件事有沒有被記錄下來」。METR 的發現是監控的觸發時機可被 agent 自己影響；摩根士丹利封鎖 agent 的理由是分不出動作歸屬。這兩件事在「高風險產品認定」這個顆粒度上完全看不見。七大原則裡的「問責」提供了法源，但要落到可執行，缺的是 agent 身分、動作層級稽核與授權範圍這三項技術規範——而這恰好是數發部被賦予「提供評估與驗證工具」職權可以切入的地方。另一件不必等 2028 年的事：ConnectWise 的攻擊路徑就是台灣醫療 IT 的形狀，HIS、PACS 雲、檢驗資訊系統、健保申報、備份與災難復原都集中在少數廠商手上，打一家廠商等於打進數十到數百家醫療機構，所以把廠商端的應用程式憑證輪替與異常登入告警納入年度資安稽核、在合約裡訂下供應鏈事件通報時限、盤點所有以服務帳號或共用帳號運行的介接，是現在就能做的三件事。 The regulation's granularity does not match agents. Taiwan's AI framework act passed its third reading on Dec 23, 2025, naming the National Science and Technology Council (NSTC) as the central competent authority and establishing a National AI Strategy Special Committee under the Executive Yuan, convened by the Premier, meeting at least annually, with NSTC as secretariat (iThome's summary of the enacted text). The committee was announced on May 21, 2026, with Premier Cho Jung-tai chairing it personally and a target of setting management rules before 2028 (CNA, 2026-05-21; Liberty Times, 2026-05-21). On risk, the act does not build a full multi-tier classification but mainly distinguishes "high-risk" AI products or systems, designated by the relevant sectoral authority in consultation with the Ministry of Digital Affairs (MODA), with mandatory notices or warnings. That is precisely the problem: the framework regulates the risk tier of a product or system, while the risk exposed this week is not "is this model accurate" but "whose account did this agent use, within what authorization scope, which irreversible actions did it take, and was any of it logged". METR's finding is that the monitor's trigger could be influenced by the agent itself; Morgan Stanley's reason for blocking is that it cannot attribute actions. At the granularity of high-risk product designation, neither is visible at all. The "accountability" principle among the act's seven gives the legal basis, but making it operational requires three technical specifications it does not have — agent identity, action-level audit and authorization scope — which is exactly where MODA's mandate to "provide assessment and verification tools" could bite. One more thing that need not wait for 2028: the ConnectWise attack path is the shape of Taiwanese health IT, where HIS, cloud PACS, laboratory systems, NHI claims, and backup and disaster recovery are concentrated in a handful of vendors, so hitting one vendor means reaching dozens to hundreds of care providers. Bringing vendors' application-credential rotation and anomalous-sign-in alerting into the annual security audit, writing supply-chain incident notification deadlines into contracts, and inventorying every integration running under a service or shared account are three things that can be done now.

  1. Red-Teaming OpenAI's Internal Agent Monitoring Systems — METR (2026-10-22)

    不要只看漏洞清單，看最後那幾條設計建議。「agent 採取的動作不應該能影響監控系統是否執行、何時執行」這一句，可以直接當成任何醫院採購臨床 agent 時的驗收條款來用——而且目前市面上幾乎沒有產品能通過。Skip the vulnerability list and read the design recommendations at the end. The line "actions agents take should not be able to influence whether or when the monitoring system runs" can be lifted directly into an acceptance clause for any hospital procuring a clinical agent — and almost nothing on the market today would pass it.

  2. Storm-0940 uses ARTEX agentic AI in ConnectWise supply chain compromise — Microsoft Security Blog (2026-10-21)

    讀它的 MITRE 對照表而不是敘事段落。裡面有一條是某 ConnectWise 管理應用程式自行指派 Global Administrator 角色，另有 Defender 偵測到跨多個 vault 的大量 Azure Key Vault secret 讀取——這兩個偵測訊號可以直接拿去問自家的雲端服務商有沒有在看。Read its MITRE mapping rather than the narrative. One entry notes a ConnectWise management application self-assigning the Global Administrator role, and Defender flagged bulk Azure Key Vault secret reads across multiple vaults — two detection signals you can take straight to your own cloud vendor and ask whether they watch for them.

  3. Formal verification at scale with Claude — Anthropic Frontier Red Team with Theorem (2026-10-22)

    本週的另一面：同一種能力被用來證明而非攻擊。Claude 對 123 個開源函式庫、239 個 fuzz test 入口點的編譯後 RISC-V 二進位做出機器可驗證的證明（約 1.8 億行 Rocq），順手重新發現 libexpat 的 CVE-2026-56132。但值得讀的是它的限制章節：「形式驗證過不等於沒有 bug」、證明覆蓋的是 musl 連結的靜態 RISC-V 二進位而非大多數人在跑的 x86／ARM 與 glibc 版本——這兩句是未來幾年所有「AI 驗證過的醫材軟體」行銷說法的照妖鏡。The week's other face: the same capability pointed at proof rather than attack. Claude produced machine-checked proofs over compiled RISC-V binaries for 239 fuzz-test entry points across 123 open-source libraries (about 180 million lines of Rocq), rediscovering libexpat's CVE-2026-56132 along the way. But the part worth reading is the limitations: "formally verified" does not mean "bug-free", and the proofs cover musl-linked static RISC-V binaries rather than the x86/ARM and glibc builds most people run — two sentences to hold against every "AI-verified medical device software" claim in the coming years.

  4. AI agents broke into 100+ company websites for about $50 each — The Next Web, reporting NorForge and Reuters (2026-10-19 onward)

    讀它的叢集分析：14 個中文語系控制面板、逾 1,100 個專案、約 10% 成功率。這組數字的用途不是恐嚇，而是讓你能估算自家外包網站的實際風險——如果你有一個沒人負責更新的站，它現在的年化被攻破機率已經不能用「我們太小不值得打」來估。Read the cluster analysis: 14 Chinese-language control panels, over 1,100 projects, roughly a 10% success rate. The use of those numbers is not alarm but estimation — if you run a site nobody owns the patching for, its annualized probability of compromise can no longer be modelled as "we are too small to be worth attacking".

  5. Donating Agent Skills to the Agentic AI Foundation — Anthropic (2026-10-22)

    Anthropic 把 Agent Skills 連同名稱、GitHub 組織與 agentskills.io 網域捐給 Linux Foundation 底下的 AAIF，自述自 2025 年 12 月標準公開以來已有逾 70 個平台整合、100 萬個 skill、近 2.8 億次安裝。重點在路線圖裡那條「給 skill 撰寫者與安裝者的安全指引」：一個 skill 就是一個會被 agent 讀進上下文並照著執行的資料夾，所以它的分發在威脅模型上等同套件管理器——而醫院資訊室現在要開始把 skill 當成醫材軟體的供應鏈元件來管。Anthropic donated Agent Skills — with the name, the GitHub organization and the agentskills.io domain — to AAIF under the Linux Foundation, reporting more than 70 platforms integrated, 1 million skills published and nearly 280 million installs since the standard went public in December 2025. The point is the roadmap item on "security guidance for skill writers and installers": a skill is a folder an agent reads into context and then follows, so distributing skills is a package manager in threat-model terms — and hospital IT now has to manage skills as supply-chain components of medical device software.
