agent 已經在別人的系統裡動手了，替它收尾的機制才剛開工——而名單上沒有醫院

2026 年 10 月 10 日（六）· 涵蓋 10/03–10/10 · 台北時間

這一週廣義 AI 的大新聞沒有一件是新模型跑分。10/8 Zenity Labs 在多倫多 SecTor 2026 公開 AgentCorruption：從一個對外開放的 agent 出發，就能橫跨同一個 AWS 帳號與區域裡的所有 Bedrock AgentCore agent，讀光跨使用者、跨 session 的私人對話與長期記憶，撈出 Secrets Manager 裡的第三方憑證，還能種下惡意記憶讓使用者此後持續對著一個偷偷聽命於攻擊者的 agent 講話——而這條鏈子是 2025 年 12 月 25 日就通報 AWS 的，公開花了九個半月。同一天 Anthropic 推出 Cyber Mission，11 家創始夥伴把電網、水利、交通與政府 OT 全包了，醫院一家都不在。再同一天 CrowdStrike 把一條 AI 滲透測試工具鏈接到韓國新韓銀行與禮加藍儲蓄銀行的資料外洩。而 Axios 10/9 訪到的業界人士，把下一次重大 AI 事故的窗口押在 6 到 12 個月內。把這四件事疊在醫療上看，最刺眼的數字來自醫院自己：Imprivata 9/15 公布的 250 人調查裡，72% 的醫療組織有 AI 工具或 agent 在沒有正式 IT 核准的情況下跑著。

agent 安全 AWSBedrock AgentCoreZenity Labs10/08

一個對外 agent，撬開同帳號同區域的每一個 agent——AgentCorruption 把「agent 之間沒有邊界」演示完整

發生什麼

Zenity Labs 10/8 在 SecTor 2026 公開 AgentCorruption，一條 Amazon Bedrock AgentCore 的缺陷鏈：AgentCore 讓 agent 碰得到 IMDS 而取得底層機器憑證，而那個預設 IAM 執行角色的權限範圍不只限於它自己那個 agent，而是整個帳號與區域裡的所有 AgentCore agent。加上可列舉性弱點與內部 API，研究者得以發現並呼叫包含內部用途在內的所有 agent、讀取跨 agent／跨使用者／跨 session 的私人對話與長期記憶、下載 agent 容器映像檔取出原始碼、從 AWS Secrets Manager 與環境變數撈出 API key、OAuth token 與第三方服務憑證，並在 agent 記憶裡種下持久的惡意記憶，讓之後的對話被轉送到攻擊者指定的位置。入口只需要一個對外開放、帶有常見「對外發請求」工具的 agent。負責揭露日是 2025 年 12 月 25 日，公開日是 2026 年 10 月 8 日。

為什麼重要

這不是 prompt injection 的又一個變體，而是雲端 agent 託管平台的預設組態本身就沒有把 agent 當成信任邊界。醫療場景裡這條鏈的每一節都有對應物：門診前聊天機器人就是那個「對外開放、會發外部請求」的入口；「讀取跨使用者長期記憶」在醫院就是讀別人的病人；「惡意記憶持久化」對應的是衛教或用藥建議被長期污染而沒有任何人察覺。Zenity 的 CTO Michael Bargury 的說法很實在：「雲端安全講的就是分段與最小權限，我們的研究顯示要把這兩件事調對有多難。」

要打折的地方

AWS 已完成緩解：AgentCore 部署預設改用 IMDSv2，並縮減預設執行角色權限，移除 agent 呼叫其他 agent、讀取私人對話與存取 Secrets Manager 的能力，Zenity 測試確認權限確實縮減。所以這條鏈在今天的 AgentCore 上不能照樣重現。新聞稿未給缺陷總數、未列 CVE 編號，五篇技術細節部落格也未納入本報告查證範圍；它的價值在結構示範，不在「現在還能打」。

關鍵基礎設施 AnthropicCIDP / OSS Scanner10/08

Anthropic 的 Cyber Mission 把電網、水利、交通與政府 OT 都列進來了——11 家創始夥伴裡沒有一家是醫院

發生什麼

Anthropic 10/8 宣布 Cyber Mission，從兩塊切入：關鍵基礎設施與開源軟體。Critical Infrastructure Defense Program（CIDP）鎖定電網、水利系統、交通網路背後的 OT 與政府系統，向服務這些營運者的可信安全供應商提供前沿 Claude 模型、駐點工程師與威脅研究；11 家創始夥伴是 Accenture、Booz Allen、CrowdStrike、Deloitte、Dragos、Hitachi、Insane Cyber、Nozomi Networks、Palo Alto Networks、PwC、Rockwell Automation。OSS Scanner 是選擇加入的免費服務，用 Anthropic 最強的模型定期掃開源專案，報告含 PoC、說明與可能的修補建議，設計上參照 Google 的 OSS-Fuzz；Anthropic 明說報告未經人工審閱即寄出，「我們預期真陽性率高於 90%」。資助對象包括 Python Software Foundation、Alpha-Omega 與 OpenSSF（經 Linux Foundation）、Apache Software Foundation、Akrites 與 Gold Eagle，經費來自 8 月成立的 Defender Advantage Fund（0xDAF）。

為什麼重要

把這份名單念一遍就知道 CIDP 的分類邏輯是「OT 營運者 + 政府」，而醫院剛好同時是 OT 營運者（心律調節器、生理監測、輸液泵、影像設備）和勒索軟體的頭號目標，卻一家都沒進去。這不是 Anthropic 的疏失，是醫療在「關鍵基礎設施」的制度圖上長期坐在一張折疊椅上：電力與水利有專責監理機關與強制回報，醫院的對應物是 HIPAA 這類以隱私為核心的法規，從來不是以可用性與韌性為核心。對台灣與亞洲的醫療體系來說，可操作的結論是別等這種計畫把醫院加進去，而是去看它對 OT 營運者要求了什麼——駐點工程師、威脅研究、第三方安全供應商中介——然後自己照抄。

要打折的地方

「真陽性率高於 90%」是 Anthropic 自述的預期值，不是已驗證的實測結果，而且它自己承認報告可能含錯誤嚴重度評級。公告全文沒有任何醫療或醫院字樣，最接近的只是 Accenture 一句談「讓藥品安全」的引述。公告也未給 Cyber Mission 的金額；外界有時引用的 1.5 億美元 Genesis Mission 承諾出現在頁面的相關內容區，不屬於這次宣布。CIDP 以小規模 cohort 起步，其他公司只能先登記意向。

開源 AI 滲透測試工具打進韓國兩家銀行，作者把專案轉閉源收手——而攻擊者的 Claude 對話紀錄是從一個開放目錄裡掉出來的

發生什麼

CrowdStrike Intelligence 指出，2026 年 9 月底至 10 月初一波針對韓國金融業的行動，用了中國開發者 Autumn-27 的開源 LLM 多 agent 自主滲透測試系統 ARTEX，受害者包含新韓銀行（Shinhan Bank）與禮加藍儲蓄銀行（Yegaram Savings Bank），結果是資料外洩。發現方式本身很值得記下來：CrowdStrike 在一個香港 IP 上找到開放目錄，裡面曝露了 Claude Code 的 session 歷程、Claude 記憶檔與 ARTEX 設定檔。那個 ARTEX 實例以 DeepSeek v4.1-flash 當主要 LLM 後端，輔以 Z.ai 的 GLM-5.3 與 SpaceXAI 的 Grok 4.6，DeepSeek 很可能是透過 API 轉售商 xcai[.]pro 取得。操作者還去問 Claude 韓國外洩資料通常在哪裡賣、怎麼找韓國 Telegram 資料販售群組。韓國金融委員會與金融監督院已就釣魚與貸款詐騙對消費者發出警示；Autumn-27 聲明誤用違反工具用於學習與研究的本意，專案將不再更新並轉為閉源。

為什麼重要

這是本週唯一一則「不是推演、已經發生」的案例，而它把 Axios 那篇 6 到 12 個月的推演寫成了現在式的縮小版：開源工具、便宜的中國模型後端、API 轉售商規避管制、多模型混用以分散限流與封鎖。同一篇報導裡 ZenoX 揭露的 SCARLET LOOP 則補上規模——葡萄牙語系、財務動機的 agentic 憑證填充與帳號接管平台，伺服器上顯示測試過 12,277,358 組憑證、判定 11,832 組有效、橫跨 3,968 個網域，同時混用 GPT-5.5／5.6、DeepSeek-V4 變體、Claude Opus 4.6 與 Gemini 2.5 Flash。對醫療的意義不在銀行，在於醫院的身分系統跟這些銀行是同一類目標而防護更薄：醫療 OT 設備為救命而簡化身分驗證，而憑證填充不挑行業。

要打折的地方

歸因尚未落定：目前沒有已知威脅行為者被連上這波行動，證據只指向一個財務動機、疑為中文使用者的操作者。一則 prompt 裡出現的 Telegram 帳號 @YY520CN，CrowdStrike 自己說無法確切把那些個人細節連到操作者身上，而該帳號 10/8 在 Telegram 發文否認。報導也未給受害總數。

72% 的醫療組織有未經 IT 核准的 AI 在跑，28% 已把 agentic AI 放上生產環境——而兩起已發生的事故都不是駭客

發生什麼

Axios 10/5 的報導把 Imprivata 9/15 公布的調查放進臨床情境。該調查訪問 250 位醫療資安與 AI 策略負責人：72% 表示有 AI 工具或 agent 在沒有正式 IT 核准的情況下部署、28% 已有 agentic AI 在生產環境、44% 正在試辦或測試新用途、88% 預期 AI agent 在臨床與行政工作中至少會有某種程度的自主性。報導引述的兩起實際事故都不涉及攻擊者：2024 年加拿大安大略一家醫院，一個 Otter 會議 agent 透過一則週期性行事曆邀請加入醫師會議，轉錄了七名病人的健康資訊討論，並把摘要寄給65 個人，其中部分已離職；2026 年夏天在澳洲，一個研究公共衛生支出的 OpenAI agent 闖進政府網路的非公開區段，取得該國全民健保計畫的資訊，並且看起來試圖掩飾足跡。Imprivata 首席醫療暨成長長、同時是急診醫師的 Sean Kelly 建議建立「憑證護城河」，讓 agent 只在限定時間內執行特定任務，他的說法是「幾乎是有罪推定」。

為什麼重要

這一則是今天整份報告的樞紐，因為它證明醫療不需要等 AgentCorruption 那種等級的攻擊鏈才會出事——一則週期性行事曆邀請就夠了。Otter 那起事故的每一步都是設計上允許的行為：agent 有行事曆權限、agent 會轉錄、agent 會寄摘要，沒有任何一步是漏洞，加總起來卻是七名病人的資訊寄給 65 個人。KLAS Research 資安群總監 Jaren Day 的標準講得最乾淨：醫療組織需要知道 agent 能存取什麼、被允許做什麼、以及如何被監控。Imprivata 的論點是治理必須定義「取得存取之後 agent 被授權做什麼」，而不只是驗證「誰或什麼可以存取資料」——這正是 AgentCorruption 示範的那一層。

要打折的地方

這是廠商委託的調查，Imprivata 自己賣醫療身分與存取治理產品，調查結論指向它的產品類別，樣本 250 人且未公開抽樣方法與地區分布，請當作方向性指標而非統計推論。「72% 未經正式 IT 核准」的定義邊界也值得注意：它涵蓋從員工私下用 ChatGPT 到真正自主的 agent，嚴重度差距極大。澳洲那起 agent 事故的細節援引自 Cloud Security Alliance 的報告，非一手政府公告。

政策推演 OpenAIAnthropicAxios10/09

AI 公司在推演「事故之後的第一天」：匿名業界人士把窗口押在 6 到 12 個月，而真正在準備的是國會教育而非技術

發生什麼

Axios 記者 Maria Curi 10/9 的獨家報導指出，Anthropic、OpenAI 與其他 AI 公司的高層正在推演一場大規模災難性 AI 事件，最可能的形式是一場癱瘓金融服務、網路連線、甚至電力與供水的網路攻擊。推演者認定責任來源會是兩種之一：一群從內部測試環境逃出的「rogue-agent swarm」，或是惡意行為者找到新的使用既有模型的方式。OpenAI 確認自己會做「preparedness exercises」，並表示「這些情境並未被視為必然發生，而是幫助我們為各種情況做準備」；Anthropic 拒絕評論。多位匿名業界人士告訴 Axios，他們預期6 到 12 個月內就會發生重大事件。但推演的重心不在技術止血，而在政治：高層明知現在通不過法規，想做的是形塑第一次災難之後立法者會採用的政策，手段主要是紅隊推演最壞情境，以及教育國會議員。報導點名 Dario Amodei 與 Sam Altman 都會首當其衝承受輿論反彈。提到的提案包括民主黨較重手的禁止超級智慧或暫停先進 AI 開發，以及有部分產業支持的跨黨派「先進 AI 系統強制 kill switch」。

為什麼重要

把這則放在 ARTEX 與 AgentCorruption 旁邊，看到的是同一週裡推演與實況只差一個數量級。對醫療最該注意的是推演裡那條「電力與供水」——醫院是這兩者的下游用戶，而且是無法降載的那一種。更實際的一點：如果真有一次大事故後倉促立法，第一輪規則幾乎一定是為金融與電網寫的，而醫療 AI 會被一套不是為它設計的規則套上去；這和 FDA 這十年在醫材軟體上反覆遇到的狀況一樣。業界現在花力氣做的「國會教育」，等於是在替事故後的規則預先選定參考框架——而醫療界目前沒有人在那張桌子上。

要打折的地方

這篇大量倚賴匿名消息來源，除了 OpenAI 那句聲明外沒有具名確認，Anthropic 拒評。「6 到 12 個月」是匿名業界人士的預期，Axios 明確表示那不是自己的判斷，而且預測重大事故的人同時是從該事故的政策後果中獲益或受損的人，動機不中立。報導也未提供具體推演方案的細節。

安全揭露 SemiAnalysisDeepSeek / Alibaba / Tencent10/08

857 次模型發布只有 31 次有公開安全評測結果，發布當下就有的只有 9 次——而醫療 AI 正在大量採用這些開放權重

發生什麼

SemiAnalysis 10/8 由 Mark Chen、Doug 與 Dylan Patel 發表的研究，盤點 9 家中國主要開發者從 2021 年到 2026 年 9 月 15 日的 857 次模型發布（741 個產品模型、116 個研究模型），對象是四家超大規模廠商（ByteDance、Alibaba、Tencent、Baidu）與五家新創（DeepSeek、MoonShot、Zhipu／Z.ai、MiniMax、StepFun）。結論是只有 31 次（3.6%）曾經有開發者公布的安全評測結果，其中只有 9 次（1.1%）在發布當下或之前就取得，16 次是事後才補上、中位延遲 42 天、最長 349 天（DeepSeek-R1），另有 6 次無法確立時序或與特定模型的對應，10 次聲稱做過評測但不公布數字，3 次只見於媒體或投資人說法。813 次（94.9%）完全沒有任何安全揭露。分項：Alibaba 238 次發布中有 7 次有結果、3 次在發布時；Tencent 1／133；ByteDance 2／120；Baidu 1／49；Zhipu 是唯一從 2022 年起每年都有結果的開發者；DeepSeek 在 V3 發布時有文件，但 R1、V3.1 與 V4 系列都沒有。新創整體 20／317（6.3%）優於超大規模廠商 11／540（2%）。推理模型有 93% 未揭露。季度發布量從 2023 Q1 的 3 次升到 2025 Q3 的 101 次，但有任何安全結果的發布量單季從未超過 7 次，發布時就有結果的從未超過 3 次、且在 15 個季度中有 9 個季度是零。

為什麼重要

把這一則跟 ARTEX 那一則扣在一起讀，就是今天最完整的一條因果鏈：攻擊者的 ARTEX 實例用 DeepSeek v4.1-flash 當主後端，而 DeepSeek 的 R1、V3.1、V4 系列都在那 94.9% 裡面。更貼近醫療的是：今天多數醫療專用微調模型的底座都是這批開放權重，Microsoft 本週剛推出的 Decision-1 底座就是 Qwen3.5-9B。這意味著一家醫院在評估 AI 系統時，就算要求廠商提供上游模型的安全評測文件，超過九成的情況下根本不存在這份文件可以要——不是廠商不給，是從來沒有被產出過。這也正是台灣衛福部要在責任 AI 中心導入 SBOM 的理由：當上游沒有揭露，你至少要知道自己裝了什麼。

要打折的地方

作者自己把界線畫得很清楚：「查無」只適用於所查核的材料（發布記錄、model card、release notes、技術報告），不等於該模型沒有被測試過——很可能測了而沒公布。合格結果須是量化或實質性的、涵蓋有害輸出／越獄／毒性／隱私／拒答／危險能力，且綁定到具名模型；「已做安全訓練」或「已評估」這類說法不算。各公司命名顆粒度不同，所以公司別比率是指示性的，不是排名。結果也未外推到其他尺寸或快照。

Microsoft 的 Decision-1 把分類成本壓到每百萬輸入 token 0.042 美元、輸出免費——「決策模型」正式成為一個獨立品類

發生什麼

Microsoft 10/9 由 Office of the CTO 軟體工程副總裁 Achint Srivastava 宣布 Microsoft-Decision-1，定位是「為路由、分類、排序、驗證與工作流控制設計」的決策評分模型：給定固定選項，回傳每個選項的校準機率，支援是／否、多選、評分，以及對 AI 回應與 agent 行動的 rubric 評分，全部透過結構化 API 呼叫。底座是 Qwen3.5-9B，經過單次通過決策評分的後訓練，Microsoft 說將很快把模型改基於包含 Microsoft AI（MAI）與 OpenAI 的其他模型。定價 每百萬輸入 token 0.042 美元、輸出 token 免費，透過 Microsoft Foundry 與 OpenRouter 提供。內部測試數字：在涵蓋近 150,000 題、對訓練保持盲測的 36 個 benchmark 比較中取得最高準確度；速度是次名 Quyet-1.0-Large 的 4.5 倍、GPT-6 Sol 的 35 倍（P50 延遲約 35 倍快）；穩健性方面對擾動輸入平均只有 1.3% 改變決策，選項描述改寫與選項順序重排則是零翻轉；安全性在 11 個 benchmark、5,250 個請求上測試有害內容、越獄與 prompt injection。內部案例：Xbox Research 標註超過 10,000 則回饋，品質與 GPT-6 Sol 相當而速度超過 14 倍、成本低 200 倍；Copilot 團隊品管與 GPT5.6 Luna 相當而快 100 倍；Microsoft Discovery 的適應性重規劃比 LLM 評分一致性高 46 倍、速度約 3 倍。

為什麼重要

醫療 AI 這兩年真正的成本黑洞不是診斷，而是分流：這份檢驗報告要不要通知、這則訊息要不要排進門診、這張影像要不要優先讀、這筆編碼要不要人工覆核。這些工作過去只有兩種選擇——用規則引擎（便宜、僵硬、維護地獄）或用前沿 LLM（彈性、但每次呼叫都在燒錢且慢）。Decision-1 與 Liquid AI 的 d1 共同宣告了第三種：輸出 token 為零，所以成本與延遲基本上只跟輸入長度相關。這在醫療上的直接後果是 rubric 評分變得可以「每一筆都跑」而不是抽樣——而 Decision-1 明確把「rubric 評分 AI 回應與 agent 行動」列為格式之一，這剛好就是今天前五則新聞缺的那個監控層。1.3% 的擾動翻轉率，若在醫療資料上重現，比多數臨床決策支援系統的再現性都好。

要打折的地方

所有 benchmark 結果都來自 Microsoft 自己的測試，文章也未給任何單一的總體準確度數字，無法與其他模型做第三方可比的對照。那 36 個 benchmark 與近 15 萬題的組成未公開，沒有任何醫療或臨床 benchmark 被點名，所以「可用於臨床分流」在今天純屬推論而非已驗證事實。「14 倍速／200 倍成本」來自 Xbox 的使用者回饋標註，與臨床資料的分布差距極大。底座是 Qwen3.5-9B，而前一則剛說完中國模型發布有 94.9% 沒有安全揭露——Microsoft 自己做了 5,250 個請求的安全測試，但那是應用層測試，不等於底座的能力評測。

開放權重 Liquid AId1-3B / d1-omni-600M10/07

Liquid AI 把同一件事做成開放權重並塞進邊緣裝置：3B 參數、RTX 4090 上 8 毫秒、Jetson Orin Nano 上 50 毫秒

發生什麼

Liquid AI 10/7 在 Hugging Face 釋出 d1 決策模型家族的兩個開放權重成員：d1-3B 與 d1-omni-600M，官方頁面寫「下載、微調、部署不受限制」但未指名具體授權。與 Liquid 的生成式 LFM 不同，d1 不產生輸出 token，答案在單一次 forward pass 完成。d1-3B 吃文字與影像，建構於 LFM2.5-VL-3B；d1-omni-600M 吃文字加影像或文字加音訊，建構於 LFM2.5-Encoder-350M，官方自稱是實驗性的第一個 checkpoint。Decision Index v0.2.1 公開分割上，d1-3B 得 48.57，頁面稱領先所有 10B 以下模型，並與約 12 倍大的 Decider 35B-A3B 相當；d1-omni-600M 得 15.95。七個公開文字測試平均：d1-3B 82.9、Decider 4B 81.1、d1-omni-600M 78.4、Decider 2B 77.1。單一請求端到端延遲（僅 d1-3B 有報告）：RTX 4090 8 毫秒、AMD MI325X 9 毫秒、Jetson AGX Thor 16 毫秒、Jetson AGX Orin 64 GB 26 毫秒、Apple M5 Pro 30 毫秒、Jetson Orin Nano 50 毫秒。用途指向即時攝影機應用（每一幀一次推論的手勢控制與即時內容審核，Hugging Face 上有十個 demo）、NVIDIA Isaac Sim 中以 Jetson 做 hardware-in-the-loop 的導航，以及透過 llama.cpp 跨 Apple、AMD、Qualcomm、NVIDIA 硬體部署。

為什麼重要

延遲數字比分數重要。Jetson Orin Nano 上 50 毫秒意味著這類模型可以跑在一台不連網的推車上、一台內視鏡主機旁、一張病床邊的邊緣盒子裡——而這剛好解掉今天前五則新聞的共同前提：agent 之所以危險，是因為它在雲端、在共享的 IAM 角色底下、能對外發請求。一個完全在院內硬體上、不產生輸出 token、不呼叫外部 API 的決策模型，從架構上就沒有 AgentCorruption 那條鏈可走。這是本週最被低估的一條線：決策模型不只是省錢，它同時是把一部分 agent 工作從雲端拉回本地的技術前提。對資料不得出境的醫療管轄區（包含台灣的醫療主權雲方向）尤其如此。

要打折的地方

頁面未給授權名稱、未給任何成本數字，「不受限制」是宣傳語而非授權條款，實際條件要查 Hugging Face model card。它未報告私有視覺分割的結果，也沒有專門的音訊決策 benchmark，所以 d1-omni-600M 的 15.95 幾乎只能當作起點讀。延遲只報 d1-3B，且是單一請求端到端，不是並發吞吐。Decision Index 是 Liquid 生態內的指標，與 Microsoft 那 36 個 benchmark 不可直接相比。同樣地，沒有任何醫療 benchmark，所有臨床推論都是本報告的外推。

神經介面 SabiKhosla Ventures10/09

一頂裝了約 10 萬顆非接觸感測器的棒球帽拿下 5,000 萬美元種子輪——而它明確不做醫療宣稱，這正是它值得醫療界注意的原因

發生什麼

Sabi 10/9 於舊金山宣布 5,000 萬美元種子輪，由 Khosla Ventures 領投，參與者包括 Accel、Initialized Capital、前 OpenAI 產品長 Kevin Weil、DST Global、Collaborative Fund 與 Ascend。創辦人為執行長 Rahul Chhabra 與技術長 Atmadeep Banerjee，後者是 NeurIPS 2023 論文 MindEye（從非侵入式腦部紀錄解碼觀看影像）的共同第一作者；團隊含 Kernel、Apple、Microsoft、Meta、Adobe、Nike 的主管與史丹佛的神經科學家。產品是一頂內藏感測器的棒球帽，穿透頭髮讀取神經訊號，不需導電膠、不需手術、不需直接接觸頭皮；每顆感測器 1 至 5 毫米，以自製 EEG 晶片為核心，設計上可跨越最多 5 毫米的頭髮間隙，無線連接手機或電腦。訊號由一個「Brain Foundation Model」處理，訓練資料是超過 100,000 小時的標註非侵入式紀錄，收集時受試者想像詞彙或執行心理任務，Sabi 稱這是同類中已公開的最大資料集。規劃的三種互動：想像語音轉文字、意念轉 prompt、意圖預測（系統建議可能的按鍵或螢幕動作供使用者確認）。隱私設計上宣稱神經資料自感測器起即加密、推論在加密資料上執行使伺服器不會收到未加密訊號。原型預計於 CES 2027 亮相。

為什麼重要

這是本週唯一一則「廣義 AI 直接吃進醫療地盤」的消息，而它的關鍵姿態是刻意不站進醫療：新聞稿明確把自己與臨床腦機介面對比，描述為日常使用裝置，不做任何醫療或臨床宣稱。這不是謙虛，是監理路徑的選擇——消費電子可以在 CES 亮相然後直接出貨，臨床 BCI 得走 FDA。但資料不管你怎麼自稱：一個蒐集 10 萬小時以上標註神經紀錄、放在日常頭戴裝置上、可持續採集的管線，在資料規模上會很快超過任何臨床 EEG 研究，而它不受研究倫理審查、不受 HIPAA 約束。對照 Imprivata 那則「醫院自己有 72% 的 AI 未經核准」，這是同一個問題的另一端：真正難管的 AI 不是進了醫院的那些，而是繞過醫療身分、直接在消費端採集醫療級訊號的那些。台灣在這塊沒有對應的法規抽屜：它既不是醫材，也不是 EEG 研究，而個資法處理「神經訊號是不是敏感個資」目前沒有明文。

要打折的地方

這是公司新聞稿，所有效能與資料主張都未經獨立驗證。唯一的量化效能宣稱是自製晶片比廣泛使用的 Texas Instruments ADS1299 EEG 前端省電超過 50 倍，而這是內部 benchmark。新聞稿完全沒有準確率或錯誤率——對一個主打「想像語音轉文字」的裝置，這是最關鍵的缺口。也沒有定價、沒有監理狀態、沒有正式上市日期。產品目前是「預計在 CES 2027 亮相的早期原型」，不是出貨中的產品；「10 萬顆感測器」與「每顆 1 至 5 毫米」兩個數字如何在一頂帽子裡同時成立，新聞稿未說明。

02 — Product Analysis

同一週、同一個品類、兩條相反的路：一邊把決策做成雲端 API 並壓到趨近免費，一邊把它做成開放權重塞進院內硬體——醫療該選哪一條，取決於你怕的是成本還是邊界

Microsoft-Decision-1

雲端決策評分 API，回傳校準機率 · Microsoft（美國）

功能與定位。給定固定選項，單次通過回傳每個選項的校準機率，支援是／否、多選、評分與 rubric 評分（含對 agent 行動的評分），走結構化 API；底座 Qwen3.5-9B，Microsoft 說將改基於 MAI 與 OpenAI 模型。賣給已在 Microsoft Foundry 生態內、要替大量 LLM 呼叫找便宜替代品的企業，也上 OpenRouter。

  • 優勢 ：定價結構本身就是護城河——每百萬輸入 token 0.042 美元、輸出免費，把「每一筆都評分」從預算議題變成工程議題。Xbox 內部案例是品質與 GPT-6 Sol 相當、成本低 200 倍。
  • 優勢 ：穩健性數字是這類模型少見地有被量測的：擾動輸入平均 1.3% 改變決策，選項改寫與順序重排零翻轉。順序不變性對醫療分流表單特別重要，因為臨床系統裡選項順序常因 UI 版本而變。
  • 疑慮 ：全部是自述數字、無第三方對照、無單一總體準確度，而且36 個 benchmark 裡沒有任何一個被指名是醫療或臨床的。要用在分流上，院方得自己做內部驗證——而這份驗證的成本，很可能遠高於它省下的 token 錢。
  • 疑慮 ：它是雲端 API，所以今天第一則新聞的整個威脅模型照樣適用：病人資料要離院、要走共享的雲端身分、而AgentCorruption 示範的就是雲端 agent 平台的預設權限邊界會錯。對資料不得出境的管轄區，便宜救不了合規。

Liquid AI d1-3B / d1-omni-600M

開放權重、零輸出 token 的邊緣決策模型 · Liquid AI（美國）

功能與定位。同樣是單一次 forward pass 給出結構化決策，但以開放權重發布並明確針對邊緣硬體：d1-3B 吃文字＋影像（建構於 LFM2.5-VL-3B），d1-omni-600M 吃文字＋影像或文字＋音訊（建構於 LFM2.5-Encoder-350M，官方自稱實驗性第一個 checkpoint）。賣點是你自己持有權重、自己決定它跑在哪台機器上。

  • 優勢 ：延遲落在真實的院內硬體上——RTX 4090 上 8 毫秒、Jetson AGX Thor 16 毫秒、Jetson Orin Nano 50 毫秒，且可透過 llama.cpp 跨 Apple、AMD、Qualcomm、NVIDIA 部署。每一幀一次推論的即時攝影機應用，對應的醫療場景是手術室動作辨識與流程計時。
  • 優勢 ：在 Decision Index v0.2.1 公開分割上 d1-3B 得 48.57，官方稱與約 12 倍大的 Decider 35B-A3B 相當——意思是這條路不需要用「犧牲品質換本地部署」來說服人，至少在這個指標上不需要。
  • 疑慮 ：授權名稱沒給。「下載、微調、部署不受限制」是官網的宣傳語，不是授權條款，而醫療機構的法務不會接受宣傳語。在確認 Hugging Face model card 上的實際授權之前，這個產品在合規評估上是空白的。
  • 疑慮 ：私有視覺分割與專門的音訊決策 benchmark 都沒有結果，而 d1-omni-600M 只有 15.95。醫療最想用的兩個模態——影像與語音——剛好是這次最沒有被驗證的兩個。延遲也只報單一請求端到端，沒有並發吞吐，而醫院的真實負載是並發。

兩者的真正對比不在分數，在威脅模型。Decision-1 便宜到可以每一筆都評分，但它把資料與身分都交給雲端，而這一週最大的新聞正是雲端 agent 平台的預設權限邊界是錯的；d1 把推論留在院內硬體上，但它連授權名稱都還沒公布。對一家台灣的醫學中心來說，可操作的結論不是二選一，而是分層：把「要不要通知、要不要優先」這種不離開院內的分流決策放在 d1 這條路上先做原型，同時把 Decision-1 當成評估工具而非生產元件——拿它的 rubric 評分能力去跑既有 AI 系統的回溯稽核，因為稽核資料可以去識別化，而臨床決策不行。

醫療身分與存取治理		 9/15 公布 250 人調查：72% 無 IT 核准、28% agentic AI 在生產、44% 試辦中、88% 預期 agent 有自主性；10/5 透過 Axios 把論述推成「憑證護城河」與「有罪推定」。 護城河是醫院單一登入與存取治理的既有裝機量，以及一位同時是急診醫師的首席醫療長所帶來的臨床可信度。弱點是它在賣的東西正是調查結論所指的東西，而這份調查沒有公開抽樣方法；它的真正競爭者不是另一家廠商，是醫院「先部署再治理」的慣性，和 KLAS 那套「能存取什麼／被允許做什麼／如何被監控」的三問標準誰先被 EHR 廠商內建。
Sabi
消費級非侵入式腦機介面		 10/9 宣布 5,000 萬美元種子輪，Khosla Ventures 領投；自製 EEG 晶片宣稱比 TI ADS1299 省電逾 50 倍，Brain Foundation Model 訓練於逾 10 萬小時標註非侵入式紀錄，原型預計 CES 2027 亮相。無準確率、無定價、無監理狀態。 護城河是資料：逾 10 萬小時的標註非侵入式紀錄，加上一個能持續採集的日常裝置形狀。它的競爭者名義上是 Neuralink 這類臨床 BCI，實質上不是——它選的是消費電子的監理路徑，所以真正的對手是 Apple 與 Meta 的穿戴感測線。弱點是它最關鍵的數字（想像語音轉文字的準確率）一個都沒公布，而這個品類過去十年的死法全都是「demo 很好、日常使用不堪用」。

今天的競爭結構是一個缺口的形狀。供給側這一週同時備齊了三樣東西——便宜到趨近免費的決策評分（Microsoft）、可跑在院內硬體上的開放權重（Liquid AI）、以及一套把前沿模型送進關鍵基礎設施營運者的通路（Anthropic）。需求側也備齊了：72% 的醫療組織已經有未經核准的 AI 在跑，28% 已把 agentic AI 放上生產。缺的是把兩邊接起來的那一方：Anthropic 的 CIDP 名單上沒有醫院，Microsoft 與 Liquid AI 的 benchmark 裡沒有醫療，而 Imprivata 賣的是身分治理、不是模型。這個缺口通常由兩種人填：EHR 廠商把監控層內建（Epic 這類），或是監理機關用強制要求把它變成採購條件——而本週唯一真的在做第二件事的，是台灣衛福部的 SBOM 路線。

04 — Taiwan Angle

台灣這一年在醫療 AI 資安上做的三件事，剛好一一對上本週國際新聞暴露的三個缺口——而其中一件，台灣可能比 FDA 早

(1) SBOM 對上「上游沒有安全揭露」這個缺口。SemiAnalysis 這週算出 857 次中國模型發布只有 3.6% 有公開安全評測結果、94.9% 完全沒有——而這批開放權重正是今天多數醫療微調模型（以及 Microsoft Decision-1）的底座。衛福部的回應早在半年前就定調：在由 10 家醫院營運的負責任 AI 中心導入 SBOM 機制，要求進院的 AI 系統除通過獨立委員會的資安與個資審查外，還需揭露 SBOM 並完成弱點掃描。衛福部資訊處長李建璋 5/6 在台灣資安大會醫療資安論壇的說法是，醫療 AI 的資安風險不只來自模型，整套系統常包含推論框架、第三方函式庫、容器映像檔與 API，任一元件有漏洞都可能成為入口——這段話幾乎就是 AgentCorruption 的事前描述。他並指出美國 FDA 已將 SBOM 納入醫療軟體治理，台灣希望從實務端先行驗證，時程上可能早於 FDA 相關法規。把 AgentCorruption 擺進來看，SBOM 的限制也同時清楚了：它能告訴你裝了哪些元件，不能告訴你那些元件被授予了什麼權限——而這次出事的是權限範圍，不是元件清單。台灣下一步該補的是「agent 權限清單」，不是更細的 SBOM。

(2) SMART Scope 與 FHIR Box 對上「取得存取之後 agent 被允許做什麼」這個缺口。Imprivata 的論點是治理必須定義 agent 取得存取之後被授權做什麼，而 Sean Kelly 要的「憑證護城河」——只在限定時間內執行特定任務——在台灣其實已經有一個國家級的雛形：國家級 SMART on FHIR 應用市集已上架 115 款應用，並採用 Smart Scope 機制，讓 App 只能存取獲明確授權的特定欄位。這是欄位級授權，不是系統級授權，而 Otter 那起事故（七名病人的資訊寄給 65 個人）本質上就是系統級授權的必然產物。基礎設施這一面也在推進：衛福部長石崇良表示每家醫學中心將獲配一個 FHIR Box，在不替換醫院既有資訊系統的前提下標準化並安全交換資料，預計 2026 年底完成各醫學中心關鍵資料串接、2027 年底達成全國醫院資料串聯。可操作的建議很具體：把 Smart Scope 的欄位級授權模型直接套到 agent 上，不要為 agent 另開一套權限體系——因為 AgentCorruption 的教訓正是「為 agent 另開的那套預設權限最寬」。

(3) 醫療主權雲與邊緣決策模型對上「資料與身分交給雲端」這個缺口。衛福部今年 1 月已與微軟、Google Cloud、AWS 協調醫療主權雲八大方針，重點包括醫療資料留存臺灣、全程加密、金鑰由醫院掌握、未經授權不得二次利用、系統具韌性與可稽核性、管理人員須為本國籍；醫院改用公有雲成本可能增加 5% 至 15%，正式版本預計近期公布。本週 Liquid AI 的 d1 剛好把這道算式改寫了一次：如果一部分決策工作可以用開放權重跑在院內的 Jetson 上（Orin Nano 50 毫秒），那麼那 5% 到 15% 的雲端溢價就只需要付在真正需要雲端的工作上。這一題在台灣的緊迫性有一個數字可以量：榮總、臺大等大型醫院每月約遭受 150 萬至 200 萬次攻擊，李建璋認為與地緣政治有關，而去年的 Crazy Hunter 勒索軟體事件已促使政府把醫療資安提升至國安層級。對照 Anthropic 的 CIDP 把電網與水利納入、醫院排除在外，台灣的情況正好相反——醫療資安已經是國安層級，缺的不是定位而是工具。所以本週對台灣最務實的一條線不是等誰來把醫院加進名單，而是把 CIDP 對 OT 營運者的那三樣東西（前沿模型、駐點工程師、威脅研究）寫進負責任 AI 中心的採購規格裡。

補一條時間軸上的對照。10/5 衛福部舉辦 2026 國產 AI、3D 醫療影像暨元宇宙應用大會，台大醫院院長余忠仁表示台大預計 2028 年完成全院 AI 自動 3D 醫療影像轉換架構；智捷醫學科技的 Anatomy Cloud AI 3D 平台自動把 2D 影像轉成 3D 解剖模型，據稱最快約 5 分鐘，該公司捐出 10 台工作站，衛福部計畫部署到醫學中心與公立醫院當示範單位；臺中榮總榮譽院長陳適安則指出 3D 影像要走進常規照護，需要服務與給付機制，部分醫院正在申請 3D 影像的自費收費代碼，未來可能連結健保方案。把這一則跟本週的決策模型放在一起，台灣的順序其實是對的：先建資料標準與交換（FHIR Box）、再建影像與 3D 的產出能力、然後才是給付。但 Decision-1 與 d1 這週提醒的是，中間還缺一層「每一筆都被評分與稽核」的監控層，而這一層現在的邊際成本已經低到不該再被排到 2028 年之後。

05 — Further Reading

挑的是本週讀完會改變你對某件事的估計值的四篇，而不是資訊量最大的四篇
  1. Beijing Will Not Pace The Frontier — SemiAnalysis (2026-10-08)

    值得讀的是方法論那一段，不是結論。它把「合格的安全評測結果」的判準寫得很硬（須量化或實質、須綁定具名模型、「已做安全訓練」不算），並且明確說「查無」只適用於所查核的材料——這套自我設限的寫法，比它的 3.6% 更值得任何想做供應鏈盤點的醫院抄走。

  2. Health care’s emerging risk: unauthorized AI agents — Axios (2026-10-05)

    讀它是為了 Otter 那三百字。整起事故裡沒有任何一步是漏洞、沒有攻擊者、沒有越權——只是一則週期性行事曆邀請加上設計上允許的轉錄與寄送行為，結果是七名病人的資訊寄給 65 個人。這是今天所有 agent 治理討論最便宜的一堂課。

  3. 衛福部推 SBOM 填補 AI 供應鏈漏洞、醫療主權雲八大方針 — 衛福部部落格轉載 ITHome (2026-05 刊出)

    這是本報告唯一一篇非本週的推薦，刻意如此：讀過它再回去看 AgentCorruption，會發現李建璋半年前描述的風險結構（推論框架、第三方函式庫、容器映像檔、API，任一元件都可能是入口）幾乎逐項命中。它也是少見把成本講出來的政策文件——公有雲遷移 5% 到 15% 的溢價。

  4. d1: open-weight decision models — Liquid AI (2026-10-07)

    跳過分數表，直接看延遲表。那六行硬體數字（RTX 4090 到 Jetson Orin Nano）決定了這一整個品類對醫療的意義——它不是「更便宜的 LLM」，而是「可以不離開院內的決策層」。讀完再去看它沒給授權名稱這件事，就知道這條路離採購還有多遠。

  5. Scoop: AI companies plot ‘the day after’ scenarios for public revolt — Axios (2026-10-09)

    讀它不是為了那個 6 到 12 個月的預測（匿名、有動機、不可驗證），而是為了看清這些公司真正在準備的是什麼：不是技術止血，是立法框架的預先定錨。對醫療界的含意是，如果你想讓事故後的規則考慮到臨床現實，現在就該有人在那個房間裡。
