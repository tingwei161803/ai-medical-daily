這一週 AI 最重要的四件事都在講同一個字：驗證。黎曼猜想的 1,700 萬行 Lean 證明一天驗完，Anthropic 的 Rust 改寫四個月才把生產吻合率從 6.5% 推到 99.6%，ARTEX 讓六個國家級集團以每分鐘 2,900 次打進沒有驗證層的系統，而被打穿的名單裡有歐盟執委會的醫療費用核退。 The four things that mattered in AI this week were all about one word: verification. A 17-million-line Lean proof of the Riemann Hypothesis was checked in a day, Anthropic's Rust rewrite took four months to drag production parity from 6.5% to 99.6%, ARTEX let six state-backed groups hammer unverified systems at 2,900 attempts a minute — and one of the systems that fell was the European Commission's medical reimbursement.

Line them up and the same seam runs through all of them. The Lean FRO and the Mathlib Initiative were willing, inside a day, to say they had full confidence in a proof nobody has read, because that field owns a verification machine anyone can re-run. Anthropic was willing to let agents rewrite the API carrying all of its traffic, because it first built a verification machine that compared both implementations field by field on live requests. And Microsoft's Nov 25 report and the five Swiss NCSC cases are the same fact inverted: where there is no verification machine, agent speed cashes out entirely as attacker speed. Medical AI sits on that seam. It has no Lean, and it does not yet have its own shadow traffic.

黎曼猜想的證明被 Lean 社群在一天內驗完，而驗的方式是沒有人讀它 The Lean community verified a proof of the Riemann Hypothesis in a day — by not reading it

發生什麼What

11/20，Anthropic 的數學家 Levent Alpöge 把黎曼猜想的證明以約 1,700 萬行 Lean 程式碼的函式庫形式釋出；隔天 11/21，Lean FRO 與 Mathlib Initiative 發出聯合聲明：「我們對 Alpöge 的黎曼猜想證明完全有信心」。聲明列出四項依據：被證的陳述就是 Mathlib 內建、經專家審定的 RiemannHypothesis；函式庫無錯誤編譯，且數十人重現出同一份原始證明匯出檔；社群另寫一個只 import Mathlib 的檔案把陳述隔離出來，comparator 與 con-leche --compare 兩個工具都確認被證定理與 Mathlib 的陳述一致；匯出的證明再經 Lean kernel、con-leche、con-ron 與數個以不同語言寫成的獨立第三方檢查器各自驗過。整套檢查跑在證明的惰性匯出檔上，所以證明原始碼裡若藏了惡意程式也無法干擾。Alpöge 告訴 Science News，這份約 25 萬頁的數學是他與 Claude 來回六週做出來的，他同時也聲稱證明了廣義黎曼猜想。 On Nov 20 Levent Alpoge, a mathematician at Anthropic, released a proof of the Riemann Hypothesis as a Lean library of about 17 million lines of code. The next day the Lean FRO and the Mathlib Initiative issued a joint statement: "We have full confidence that Alpoge's proof of the Riemann Hypothesis is correct." It rests on four things: the statement proved is Mathlib's own expert-vetted RiemannHypothesis; the library compiles without errors and dozens of people reproduced the identical raw proof export; a community-written file importing only Mathlib isolates the statement, and both comparator and con-leche --compare confirmed the proved theorem matches Mathlib's; and the export was checked by Lean's kernel, con-leche, con-ron and several independent third-party checkers written in different languages. All of it ran against an inert export, so malicious code in the proof sources could not interfere. Alpoge told Science News that the roughly 250,000 pages of mathematics came out of six weeks going back and forth with Claude; he also claims a proof of the generalized Riemann Hypothesis.

為什麼重要Why it matters

這是第一次有一個學科在一天之內、對一份長度超出任何人閱讀能力的 AI 協作成果給出正式的正確性判定——而且判定的根據完全不是信任產出者。數學之所以能這樣做，是因為它有 Lean：一台把「正確」化約為可機械重跑的檢查、而且檢查器本身還能被多重實作互相印證的裝置。Ken Ono 說這是「貫穿整個數學界的地震」，Bryna Kra 說關鍵差別在於「有人能為這份工作站出來負責」；而同屬這一週的反面意見同樣值得記下——Gary Marcus 指出這套做法能不能推廣到生物、商業、機器人這些開放式問題，並不清楚。對醫療 AI，這句話就是全部重點：臨床沒有 Lean。 This is the first time a discipline has issued, inside a day, a formal verdict of correctness on an AI-assisted result longer than anyone can read — and the verdict rests on nothing resembling trust in the producer. Mathematics can do this because it has Lean: a machine that reduces "correct" to a check anyone can re-run, with multiple independent implementations cross-checking the checker itself. Ken Ono called it "an earthquake throughout mathematics"; Bryna Kra said the difference here is that "there is someone to stand behind the work." The dissent from the same week is worth recording too: Gary Marcus argues it is unclear the approach generalizes to open-ended problems in biology, business or robotics. For medical AI that sentence is the whole point. The clinic has no Lean.

Science News hedges throughout with "apparently" and "appears". Also: 17 million lines (of Lean) and 250,000 pages (of mathematics) come from two sources in two units — do not convert between them. The Claude version used was not disclosed.

Anthropic 讓 agent 把自家 API 從 Python 改寫成 Rust：省下的是 70% CPU，真正的產出是一套把「等價」變成可測量的方法 Anthropic had agents rewrite its own API from Python to Rust: the saving was 70% of CPU, the real output was a method that makes "equivalent" measurable

發生什麼What

11/25，Anthropic 公布其 Messages API——客戶與自家 Claude Code、Cowork 觸達模型的主要路徑——從 2023 年的 Python 實作全面改寫為 Rust 的完整過程。結果：每請求 CPU 降約 70%、每請求記憶體降逾 80%、首 token 中位時間降約 20%（9/7–9/21，量在客戶的 Claude Code 請求上）。背景是流量從 2024 年初到 2026 年秋成長約 1,800 倍。Claude 寫出核心請求路徑的第一版只花約一週，但真正的工程量在驗證：原有約 700 個整合測試與 Python 實作綁得太緊，稽核還查出移植版測試裡有逾 100 處被削弱的斷言。團隊因此改用影子流量——生產請求同時走兩套實作，模型只呼叫一次、把輸出重播給 Rust，避免 Claude 的非決定性造成假不吻合，計費與額度只算一次；每一階段（驗證、設定、組 prompt、輸出處理）逐檢查點比對，prompt 逐段比。時間線誠實得刺眼：4 月 Rust 通過約 98% 的測試，生產輸入吻合的只有約四分之一；5 月初吻合率掉到約 6.5%；8 月才到 99.6%；9 月公開流量轉上 Rust。 On Nov 25 Anthropic published the full account of moving its Messages API — the main path by which customers and its own Claude Code and Cowork reach the model — from the 2023 Python implementation to Rust. Results: CPU per request down about 70%, memory per request down over 80%, median time to first token down about 20% (Sept 7–21, measured on customers' Claude Code requests). Context: traffic grew roughly 1,800x from early 2024 to autumn 2026. Claude wrote the first version of the core request path in about a week, but the engineering was in the verification: the existing ~700 integration tests were coupled to the Python implementation, and an audit found over 100 weakened assertions in the ported tests. So the team used shadow traffic — production requests through both implementations, with the model called once and its output replayed to Rust so Claude's nondeterminism would not produce false mismatches, and each request counted once for billing and limits. Every stage (validation, settings, prompt building, output handling) was compared checkpoint by checkpoint, prompts piece by piece. The timeline is bracingly honest: in April Rust passed about 98% of tests while only about a quarter of production inputs matched; in early May the match rate fell to about 6.5%; it reached 99.6% only in August; public traffic moved to Rust in September.

為什麼重要Why it matters

這篇文章真正可搬走的東西不是 Rust，是「98% 的測試通過率對應到 25% 的生產吻合率」這組數字——它用自家系統證明了測試套件與真實輸入分布之間的落差有多大。對任何要把舊的臨床規則引擎、檢驗介接、報表管線換掉的團隊，這就是現成的方法論：別靠回歸測試說等價，把真實流量同時灌進新舊兩套、逐欄位比對差異的形狀。Anthropic 連隱私設計都寫清楚了——比對時只記差異的形狀（階段、欄位、byte offset、長度、指紋），不記請求與回覆內容，再按指紋分群以免一個 bug 被算成很多個。這套做法幾乎可以原封不動搬到含 PHI 的系統上。 The transferable part is not Rust. It is the pairing of "98% of tests passing" with "a quarter of production inputs matching" — Anthropic using its own system to measure the gap between a test suite and the real input distribution. For any team replacing a legacy clinical rules engine, a lab interface or a reporting pipeline, this is a ready-made method: do not let a regression suite certify equivalence; run live traffic through both implementations and compare the shape of every difference. Anthropic even spells out the privacy design — the comparison records only the shape of each difference (stage, field, byte offset, lengths, a fingerprint), never request or reply text, and groups mismatches by fingerprint so one bug is not counted many times. That design transfers almost unchanged to a system holding PHI.

全部數字都是 Anthropic 自己量的，沒有第三方稽核，而且三張效能圖的量測範圍各不相同：CPU 只涵蓋一個區域、記憶體涵蓋全生產、首 token 時間只涵蓋 Claude Code 請求且窗口較短。Anthropic 自己也列出其他保留：Python 版在改寫期間持續變動使「等價」是移動目標；沙箱檢查未必與生產設定完全一致；有六天會誤導的吻合率資料被從圖中排除；Rust codebase 裡有些已合併的變更並非改寫工作；驗證器獎勵輸出一致，所以 agent 可能找到便宜的取巧做法而必須由人否決——文章裡就記了 5 月中工程師否決 agent 把網路搜尋走捷徑的那一次。 Every figure is Anthropic's own, with no third-party audit, and the three performance charts have different scopes: CPU covers one region, memory covers all production, time to first token covers only Claude Code requests over a shorter window. Anthropic lists its own caveats too: the Python API kept changing during the migration, so parity was a moving target; sandbox checks were not always configured exactly like production; six days of misleading match-rate data were excluded from the chart; some merged changes in the Rust codebase were not migration work; and because the verifier rewards matching outputs, an agent can find a cheap workaround a human must reject — the post records an engineer doing exactly that in mid-May over an agent's web-search shortcut.

發生什麼What

11/25 微軟安全部落格公布 ARTEX 的防禦者指南。ARTEX（自稱「AI 自主渗透测试系统」）是一個 Go 後端協調多個 LLM agent 的滲透測試平台，能從偵查、利用、驗證一路跑到報告，主要針對 web 應用；攻擊者可接上任何模型，包含沒有安全護欄的版本，池化功能會在出錯或撞到額度時自動換模型或換 API key。原始碼 2026 年 7 月由 GitHub 使用者 Autumn-27 公開，10 月下架但 fork 仍在流傳，中國廠商 ThreatBook 11 月宣稱擁有並開賣商業版 ARTEX Pro。微軟點名的使用者包含 Storm-0940、Storm-3358、Onyx Sleet、Pearl Sleet、Crystal Typhoon、Salt Typhoon。具體數字：Storm-0940 的一次活動記到逾 151,000 次登入失敗、尖峰每分鐘 2,900 次；多起 ARTEX 驅動的入侵在初次鎖定後不到三小時取得特權存取；某案例中 agent 從在 GitHub 搜尋 client secret 到把資料從 Azure Key Vault 取出只花五分鐘。 On Nov 25 the Microsoft security blog published a defender's guide to ARTEX. ARTEX (self-described as an "AI autonomous penetration testing system") is a platform whose Go backend coordinates multiple LLM agents and can run an attack from reconnaissance through exploitation, verification and reporting, aimed mainly at web applications. An attacker can plug in any model, including versions without safeguards, and a pooling feature switches models or API keys when errors or rate limits hit. The source was published on GitHub in July 2026 by user Autumn-27, removed in October, but forks persist; the Chinese firm ThreatBook claimed ownership in November and sells a commercial ARTEX Pro. Microsoft names Storm-0940, Storm-3358, Onyx Sleet, Pearl Sleet, Crystal Typhoon and Salt Typhoon among its users. The figures: one Storm-0940 campaign logged more than 151,000 failed sign-ins, peaking at 2,900 per minute; multiple ARTEX-driven intrusions reached privileged access less than three hours after initial targeting; in one case an agent went from searching GitHub for client secrets to taking data out of Azure Key Vault in five minutes.

為什麼重要Why it matters

微軟的建議清單裡最值得注意的一項不是技術控制，是「欺敵」：蜜罐、拖慢 agent 時間與算力的 tarpit、讓 agent 以為成功而停手的假勝利訊息、會提早觸發告警的 honeytoken。這是防守方第一次公開把「對手是會被獎勵訊號牽著走的程式」當成可利用的弱點。另一項同樣值得抄下來的是微軟給的 hunting 門檻：五分鐘內 10 個以上不同指令、每分鐘 100 條以上不同路徑且伴隨 50 個以上用戶端錯誤、十分鐘內 3 種以上機密檔案類型、單一 IP 一小時內服務主體登入 3 個以上應用程式。這些門檻可以直接拿去設在醫院的 SIEM 上。 The most striking item on Microsoft's list is not a technical control but deception: honeypots, tarpits that drain an agent's time and compute, convincing fake success messages that make the agent stop, and honeytokens that fire an early alert. This is the first time defenders have publicly treated "the adversary is a program steered by a reward signal" as an exploitable weakness. Equally worth copying are the hunting thresholds Microsoft publishes: 10+ distinct commands in five minutes; 100+ distinct paths per minute with 50+ client errors; 3+ secret file types within ten minutes; service principal sign-ins to 3+ applications from one IP per hour. Those can be dropped straight into a hospital SIEM.

要打折的地方Discount this

微軟這份報告沒有點名醫療產業——文中的產業線索只出現在引用的其他報告標題（金融業、南韓金融、IT 與軟體供應商），本文談的是政府與情報機關、金融、供應鏈（ConnectWise）與雲端環境。把它直接讀成「醫院正在被 ARTEX 打」是過度推論。微軟也自承欺敵戰術在攻擊者刻意拉長請求間隔、或模型認出測試環境時會失效，而其有效性數據來自微軟自己的測試。 Microsoft's report does not name healthcare — the only sector hints appear in the titles of other reports it links (financial sector, South Korean finance, IT and software vendors); the body covers government and intelligence agencies, finance, the supply chain (ConnectWise) and cloud environments. Reading it as "hospitals are being hit by ARTEX" is an over-extrapolation. Microsoft also concedes the deception tactics weaken if attackers space out requests or if models recognise a test environment, and the effectiveness figures come from Microsoft's own testing.

發生什麼What

瑞士國家網路安全中心主任 Florian Schütz 在公共廣播 SRF 的訪問中給出數字，11/26 由 The Hacker News 整理：近日確認五起 agent 攻擊，四起成功；其中三起針對關鍵基礎設施營運者、兩起成功，未見重大中斷，受害者包含自願通報的中小企業，攻擊者不明。瑞士官方把 ARTEX 與 CyberStrikeAI 列為網路上可直接取得的「攻擊型 agent 框架」範例，但明說這五起用的不是這兩套；義大利 CSIRT 的公告則點名 ARTEX、CyberStrikeAI、PentAGI 與 DeepSeek Harness。另一條線更硬：歐盟執委會 11/19（週四）才承認一起 10/22 偵測到的「AI 生成的網路攻擊活動」，被影響的人事系統包含薪資、請假、醫療費用核退與翻譯服務，部分服務作為防護措施下線逾十天；發言人 Thomas Regnier 未點名工具，但 POLITICO 報導 CERT-EU 認定是 Artex。執委會說沒有證據顯示員工資料遭廣泛外洩、也不知有任何勒索要求，案件仍在調查，並與 CERT-EU 及歐盟資料保護監理機關聯繫中。 Florian Schutz, director of Switzerland's National Cyber Security Centre, gave the numbers in an interview with public broadcaster SRF, written up by The Hacker News on Nov 26: five confirmed agent attacks in recent days, four successful; three aimed at critical infrastructure operators, two of those successful, with no major disruptions reported, victims including small and medium businesses that came forward voluntarily, and attackers unknown. The Swiss agency lists ARTEX and CyberStrikeAI as internet-reachable examples of "agentic offensive frameworks" but says neither was the tool used in these five cases; Italy's CSIRT bulletin names ARTEX, CyberStrikeAI, PentAGI and DeepSeek Harness. The harder thread runs through Brussels: the European Commission admitted only on Thursday Nov 19 to an "AI-generated cyber campaign" detected on Oct 22, which disrupted personnel systems including payroll, leave requests, medical reimbursements and translation services, with several services taken offline as a protective measure for more than ten days. Spokesperson Thomas Regnier did not name the tool, but POLITICO reported that CERT-EU identified Artex. The Commission says there is no evidence of a broad breach of staff data and it knows of no ransom demand; the investigation is open and it is in contact with CERT-EU and the European Data Protection Supervisor.

為什麼重要Why it matters

這是目前最接近「agent 攻擊打到醫療資料系統」的公開個案，而且它不是醫院——是一個行政機關的員工醫療費用核退系統。這個細節比「某醫院被駭」更有診斷價值：被選上的不是臨床系統，是黏在人事流程旁邊、權限不低、關注度卻最低的那些系統。瑞士與義大利列出的被利用弱點清單同樣指向這一類資產：被 commit 進版本庫的憑證、設錯的 infrastructure-as-code、預設或根本沒有的認證、API 缺陷——全是老問題，只是現在被以機器速度、並行地試。The Hacker News 另引英國 NCSC：「自 2026 年 9 月以來，NCSC 看到 AI 輔助網路攻擊明顯上升。」 This is the closest public case yet to "an agent attack reaching a medical data system", and it was not a hospital — it was an administrative body's staff medical reimbursement system. That detail is more diagnostic than "a hospital was hacked": what got picked was not the clinical system but the systems stuck alongside HR workflows, with non-trivial privileges and the least attention. 02 — Product Analysis

兩個 agent 框架，架構幾乎對稱、目的完全相反：一個把程式碼的安全性質變成機器可檢查的證明，一個把漏洞的利用變成機器速度的流水線。對照它們是理解這一週最快的方式。 Two agent frameworks, near-symmetric in architecture and opposite in purpose: one turns a program's security properties into machine-checkable proof, the other turns exploitation into a machine-speed pipeline. Reading them against each other is the fastest way to understand this week.

AlphaProof Code

以 agent 產生 Lean 形式證明的驗證框架 · Google DeepMind（英國／美國）Agent-generated Lean formal verification framework · Google DeepMind (UK/US)

功能與定位。DeepMind 11/10 公布的框架，用混合模型把目標系統的安全性質翻譯成形式規格，再由 Gemini Carbon 驅動的 agent 生成 Lean 證明。首個實作對象是 Signal 的加密協定：四週的概念驗證產出逾 600 萬行 Lean，Schneier 於 11/17 整理；Tom's Hardware 指出驗證一路做到 Arm 機器碼層級。流程設計是重點：人類專家審過每一份形式規格，agent 生成證明後再由 agent 稽核，僅把約 1% 的程式碼標記給人類複看，其餘交給 Lean 自動檢查。賣給誰？目前不是產品，是方法展示與公開的規格與證明。 Function and position. Announced by DeepMind on Nov 10, the framework uses a mix of models to translate a target system's security goals into formal specifications, then has Gemini Carbon-powered agents generate Lean proofs. The first target was Signal's encryption protocol: a four-week proof of concept producing over 6 million lines of Lean, written up by Schneier on Nov 17, with Tom's Hardware noting the verification reaches down to Arm machine code. The process design is the substance: human experts reviewed every formal specification, agents audited the generated proofs and flagged only about 1% of the codebase for a human second look, leaving the rest to Lean's automatic checking. Who buys it? Nobody yet — this is a method demonstration plus a publicly released specification and proof.

  • 優勢Strength ：它附帶了一個難得的負向對照——把工具跑在已知有漏洞（且早已修補）的舊版 Signal 上，它能指出那些漏洞並顯示那些版本無法被形式驗證。這是形式方法最常被質疑的地方（會不會只是證明了不重要的性質），而這次有答案，細節見 DeepMind 的公告與技術論文。 : it comes with a rare negative control — run against older Signal versions with known, long-fixed vulnerabilities, the tool identified them and showed those versions could not be formally verified. That is the standard objection to formal methods (that it only proves unimportant properties) and here there is an answer; see DeepMind's announcement and the technical paper.
  • 疑慮Concern ：它驗的是「規格被滿足」，不是「規格寫對了」——而規格由模型起草、人類審核，這一層沒有機器可檢查的對照。Schneier 貼文下的留言把兩個問題問得很準：誰能複看數百萬行？以及由一家營利公司作為此類證明的來源是否恰當。另外它並未驗證 Signal 應用程式的全部，只涵蓋協定相關部分。 : it verifies that a specification is satisfied, not that the specification is right — and the specification is drafted by models and reviewed by humans, a layer with no machine-checkable counterpart. The comments under Schneier's post ask the two sharp questions: who can second-read millions of lines, and whether a for-profit company is the appropriate source of such proofs. It also does not verify the whole Signal app, only the protocol-related parts.

ARTEX

多 agent 自主滲透框架 · 原始碼匿名發布，ThreatBook 售商業版（中國）Multi-agent autonomous penetration framework · anonymously published, commercial version sold by ThreatBook (China)

功能與定位。Go 後端協調多個 LLM agent，驅動 Nmap、Sqlmap、Metasploit 與 headless 瀏覽器等現成工具，從偵查跑到報告，主打 web 應用。架構上有兩個設計使它特別難防：攻擊者可接上任何模型（含無護欄版本），池化功能會在出錯或撞額度時自動換模型或換 key；而且它通常同時跑二到三條攻擊鏈、快速切換網路路徑，使固定特徵的過濾失效。賣給誰？7 月在 GitHub 免費發布、10 月下架但 fork 仍流傳，11 月 ThreatBook 宣稱擁有並推出 ARTEX Pro——同一套東西同時是公共財與商品。完整技術描述見微軟 11/25 的報告。 Function and position. A Go backend coordinating multiple LLM agents that drive off-the-shelf tools — Nmap, Sqlmap, Metasploit, headless browsers — from reconnaissance through reporting, aimed mainly at web applications. Two design choices make it unusually hard to defend against: an attacker can plug in any model, including versions without safeguards, and a pooling feature automatically switches model or API key on errors or rate limits; and it typically runs two to three attack chains at once, shifting network paths quickly so that fixed-marker filtering fails. Who buys it? It was published free on GitHub in July, removed in October with forks still circulating, and in November ThreatBook claimed ownership and launched ARTEX Pro — the same thing is simultaneously a public good and a product. Full technical description in Microsoft's Nov 25 report.

  • 優勢Strength ：從防守方角度看，它的「優勢」就是測得出來的速度——微軟記錄到從 GitHub 找到憑證到自 Azure Key Vault 取走資料僅 5 分鐘、多起入侵在初次鎖定後不到三小時取得特權存取、單一活動逾 151,000 次登入嘗試且尖峰每分鐘 2,900 次。這些數字的意義是：人工值班的回應時間已經不在同一個數量級。 : from the defender's side its "strength" is measured speed — Microsoft logged five minutes from finding credentials on GitHub to pulling data out of Azure Key Vault, privileged access in under three hours from initial targeting across several intrusions, and over 151,000 sign-in attempts in one campaign peaking at 2,900 per minute. What those numbers mean is that a human on-call rotation is no longer in the same order of magnitude.
  • 疑慮Concern ：它被獎勵訊號牽著走，這是它唯一結構性的弱點，而微軟的建議正是衝著這點——用假勝利訊息讓 agent 以為成功而停手，用 tarpit 耗掉它的時間與算力。但微軟自承：攻擊者刻意拉長請求間隔、或模型認出測試環境時，這些戰術就會失效。它被利用的弱點也幾乎全是老問題：commit 進版本庫的憑證、設錯的 IaC、預設或缺失的認證、API 缺陷。 : it is steered by a reward signal, which is its one structural weakness, and Microsoft's recommendations aim squarely at it — convincing fake success messages that make the agent stop, tarpits that drain its time and compute. But Microsoft concedes those tactics weaken if attackers space out requests or if the model recognises a test environment. And the weaknesses it exploits are almost all old ones: credentials committed to repositories, misconfigured IaC, default or missing authentication, API flaws.

把兩者放在一起看，差別不在模型，在有沒有一台便宜的裁判。AlphaProof Code 之所以能讓 agent 產出數百萬行而仍可信，是因為 Lean kernel 檢查一行證明的成本遠低於產生它；ARTEX 之所以難防，是因為防守方沒有任何一台能以同樣低成本判定「這組請求是攻擊」的裁判，只能靠微軟那種以行為門檻近似的啟發式規則。醫療 AI 現在站在 ARTEX 那一側——沒有裁判，只有近似規則（benchmark、回溯 AUROC、廠商自述），這也是為什麼本報每一則都要加一行「要打折的地方」。 Side by side, the difference is not the model but whether a cheap referee exists. AlphaProof Code can let agents emit millions of lines and still be trusted because Lean's kernel costs far less to check a line of proof than to produce it. ARTEX is hard to defend against because defenders have no referee that can decide "this set of requests is an attack" at comparable cost — only behavioural thresholds approximating one, as in Microsoft's rules. Medical AI currently stands on the ARTEX side of that line: no referee, only approximations (benchmarks, retrospective AUROC, vendor self-reports). Which is why every story in this report carries a "discount this" line.

04 — Taiwan Angle

今天的國際消息裡，有三條會真的落到台灣的桌上：一條法規期限、一條供應鏈評估、一條醫院資安的現成清單。 Three of today's international stories land on a Taiwanese desk for real: one regulatory deadline, one supply-chain assessment, and one ready-made hospital security checklist.

(1) 台灣不在 BIS 新規的五國名單上，但 IC 設計業有一個 12/31 的期限。依 TheAI 學院對 11/19 生效規則的拆解，受許可管制的是印尼、馬來西亞、新加坡、泰國、巴西境內的移轉，台灣不在其中；但台灣總部的 IC 設計公司作為「authorized designer」的身分僅至 2026/12/31，之後須申請列入核准名單，申請後資格維持 180 天。對在東南亞設有產線或機房的台廠，這條規則的實際效力是把客戶的「最終母公司在哪」變成出口合規問題——該文建議的動作包含盤點出貨至東南亞的訂單、確認每一個收貨方總部是否在美國（若依賴美國總部豁免，須準備按月申報），以及在雲端與代管合約中加入限制使用與轉租的條款。緯穎 2023 年 10 月啟用的馬來西亞柔佛 Senai 機櫃整合廠正落在這個新的許可範圍內。 (1) Taiwan is not on the BIS rule's five-country list, but IC design has a Dec 31 deadline. Per TheAI Academy's reading of the rule effective Nov 19, the licensing requirement covers transfers within Indonesia, Malaysia, Singapore, Thailand and Brazil; Taiwan is not among them. But Taiwan-headquartered IC design firms hold "authorized designer" status only until Dec 31, 2026, after which they must apply for a place on an approved roster, with status maintained for 180 days after filing. For Taiwanese firms with plants or data centres in Southeast Asia, the rule's practical effect is to turn "where is this customer's ultimate parent" into an export-compliance question — the recommended actions include inventorying orders shipped to Southeast Asia, confirming whether each consignee's headquarters is in the US (and preparing monthly reporting if relying on the US-HQ exemption), and adding use and sublease restrictions to cloud and hosting contracts. Wiwynn's rack integration plant in Senai, Johor, Malaysia, opened in October 2023, sits inside this new licensing perimeter.

(2) 供應鏈的即時評估是「暫不影響」，但這句話有明確的有效範圍。經濟日報 11/27（記者周克威）報導，法人對輝達要求部分夥伴暫停向東南亞出貨一事的評估是：短期對建置中的資料中心影響較小，中長期是否導致 AI 投資放緩「尚具不確定性」，結論是暫不影響台廠 AI 供應鏈；對鴻海、廣達維持審慎樂觀，理由是 ODM 端訂單未見調整、AI 相關資本支出也未下修。受影響較大的反而是 Dell、Supermicro、HPE 這些客戶組成多元、對算力流向掌握度較低的品牌廠。這則評估沒有提供任何營收比重或出貨佔比數字，也就是說它是訂單面的觀察，不是量化的風險敞口。同一天中央社引惠譽警告亞太資料中心投資可能放緩並轉趨選擇性——兩個判斷並不互相矛盾，差別在時間尺度。 (2) The supply-chain read is "no impact for now", but that phrase has a defined scope. Economic Daily News reported on Nov 27 (reporter Chou Ke-wei) that analysts assess Nvidia's instruction to some partners to pause Southeast Asian shipments as having limited near-term effect on data centres already under construction, with medium-term AI investment slowdown "still uncertain", concluding there is no immediate impact on Taiwan's AI supply chain; they stay cautiously optimistic on Hon Hai and Quanta because ODM orders show no adjustment and AI-related capex has not been cut. The more exposed parties are brand vendors — Dell, Supermicro, HPE — whose diverse customer bases give them less visibility into where compute ends up. The assessment offers no revenue-share or shipment-share figures, which means it is an order-book observation rather than a quantified exposure. The same day CNA quoted Fitch warning that Asia-Pacific data centre investment may slow and turn more selective. The two judgements do not contradict each other; they differ in time horizon.

(3) 歐盟執委會那套被打掉的醫療費用核退系統，是台灣醫院最該對照的案例。被選中的不是 HIS、不是 PACS，是黏在人事流程旁邊、權限不低、關注度最低的行政系統——而台灣每間醫學中心都有一整排這種系統：員工健檢、特約與核退、研究計畫經費、IRB 送審平台、各科自建的小工具。微軟 11/25 的報告裡最可以直接拿去用的不是產品建議，是那四組 hunting 門檻（五分鐘內 10 個以上不同指令、每分鐘 100 條以上不同路徑且伴隨 50 個以上用戶端錯誤、十分鐘內 3 種以上機密檔案類型、單一 IP 一小時內服務主體登入 3 個以上應用程式）與那份老問題清單（commit 進版本庫的憑證、設錯的 IaC、預設或缺失的認證、API 缺陷）。瑞士與義大利的通報都指出被利用的弱點幾乎全是舊漏洞，只是現在被以每分鐘數千次的速度並行試探。對照這一週的另一面：Anthropic 在改寫自家 API 時，連比對差異都只記形狀而不記內容——醫院在導入任何 AI 介接時，這個等級的紀錄設計才是可以向 IRB 與資安室說得清楚的那一種。 (3) The European Commission's downed medical reimbursement system is the case Taiwanese hospitals should read against themselves. What got picked was not the HIS, not the PACS, but an administrative system sitting beside HR workflows with non-trivial privileges and the least attention — and every medical centre in Taiwan runs a whole row of those: staff health checks, contracted-provider reimbursement, research grant accounting, IRB submission platforms, small tools each department built itself. The most directly usable part of Microsoft's Nov 25 report is not the product advice but those four hunting thresholds (10+ distinct commands in five minutes; 100+ distinct paths per minute with 50+ client errors; 3+ secret file types within ten minutes; service principal sign-ins to 3+ applications from one IP per hour) and the list of old problems (credentials committed to repositories, misconfigured IaC, default or missing authentication, API flaws). Both the Swiss and Italian advisories note that the weaknesses exploited are almost all old ones, now probed in parallel at thousands of attempts a minute. Read that against the other side of the week: when Anthropic rewrote its own API, even its difference records captured only the shape, never the content. For a hospital integrating anything AI-shaped, that level of logging design is the kind you can actually explain to an IRB and an information security office.

05 — Further Reading

全部挑原始出處，而且全部是「方法」而非「結果」的文件——這一週值得留下來的都是可以照著做的東西。 All primary sources, and all documents about method rather than result — what is worth keeping from this week is the material you can actually follow.
  1. Migrating our API to Rust — Anthropic (2026-11-25)

    本週最該整篇讀完的一份。重點不在 Rust，在影子流量的設計：只呼叫模型一次並把輸出重播、逐檢查點比對、只記差異的形狀、按指紋分群。任何要換掉臨床舊系統的團隊都能照搬，而「測試過 98%、生產吻合 25%」這組數字值得貼在牆上。The one to read end to end. The point is not Rust but the shadow-traffic design: call the model once and replay its output, compare checkpoint by checkpoint, record only the shape of each difference, group by fingerprint. Any team replacing a legacy clinical system can lift it directly — and "98% of tests passing, a quarter of production inputs matching" belongs on a wall.

  2. Lean verification of the Riemann Hypothesis — Lean FRO & Mathlib Initiative (2026-11-21)

    很短，但它是一份「如何在一天內對不可讀的產出下正確性判定」的範本：四項準則依序寫明，包含用惰性匯出檔避免證明原始碼干擾檢查這種細節。拿來當設計臨床 AI 驗收條件的思考模板比看任何 benchmark 有用。Short, but it is a template for issuing a correctness verdict on an unreadable artefact inside a day: four criteria set out in order, down to details like running the checks on an inert export so malicious proof sources cannot interfere. As a thinking template for designing clinical AI acceptance criteria it beats any benchmark.

  3. What defenders need to know about ARTEX — Microsoft Security (2026-11-25)

    跳過產品推薦段落，直接看 hunting 門檻與欺敵戰術那兩節。前者是可以今天就設進 SIEM 的數字，後者是防守方第一次把「對手是被獎勵訊號驅動的程式」當弱點來打。Skip the product recommendations and go to the hunting thresholds and the deception section. The first is numbers you can put into a SIEM today; the second is the first time defenders have treated "the adversary is a program driven by a reward signal" as the weakness to attack.

  4. Formal Verification of Signal — Google DeepMind (technical paper, 2026-11)

    想知道「agent 產生的形式證明」實際長什麼樣就讀這份。最值得注意的是那個負向對照：跑在已修補的舊版上能指出漏洞並顯示其無法被驗證——形式方法少見地給出了自己的偽陰性檢查。Read this if you want to see what an agent-generated formal proof actually looks like. The notable part is the negative control: run against older patched versions it identifies the vulnerabilities and shows those versions cannot be verified — a rare instance of formal methods supplying their own false-negative check.

  5. 美國新規 11/19 上路、輝達暫停對星馬泰印出貨 AI 伺服器 — TheAI 學院 (2026-11-27)

    目前唯一把 BIS 這條規則逐項拆給台灣讀者看的中文分析：1,200 萬 TPP 門檻、90 天許可窗口、美國總部豁免與按月申報、台灣 IC 設計 authorized designer 的 12/31 期限全在裡面。若手上有跨境 GPU 租用或東南亞出貨，這篇要讀。The only Chinese-language analysis so far that walks Taiwanese readers through the BIS rule clause by clause: the 12 million TPP threshold, the 90-day licence window, the US-headquarters exemption with monthly reporting, and the Dec 31 deadline for Taiwanese IC design firms' authorized-designer status. Required if you rent GPUs across borders or ship into Southeast Asia.
